`pyproject.toml`, `CodeGraphIndex._build` возвращает только `scan_python` и не
смотрит `package.json`, `Cargo.toml`, `tsconfig.json`. C# в этот список маркеров
не входит вовсе (`codegraph/index.py`).

`KbEdgeKind`: `imports`, `uses_type`, `inherits`, `project_ref`, `code_ref`,
`depends_on`, `supersedes`, `links`. Значения `implements` и `call` нет.
`call` в 0.1.4 не добавляется: рёбра вызовов раздувают CTE и RSS.

`ast_skeleton_cache` ключуется полным `file_sha256`. Смена тела при той же
сигнатуре — промах кэша, хотя текст скелета тот же. Префикс при этом уже
стабилен, если в него входит скелет, а не тело. Выигрыш `interface_hash` —
не пересобирать рёбра и не вытеснять скелет.

`vault_files` уже хранит `frontmatter_hash`, `body_hash`, `mtime_ns`, `inode`,
`last_writer`, `pending_write`. Сторож после истечения TTL или после выхода
демона (`IDLE_EXIT_S = 15`) эти колонки не использует: книга эха умирает вместе
с процессом.

## 2. Решения

Здесь концепция расходится с кодом, с уже принятым 0.1.3 или с внешним
ограничением. В работу берётся решение из этого раздела.

1. **Индекс полиглотный.** Корень с `pyproject.toml` и `package.json` даёт оба
   графа. Python-идентификаторы остаются прежними (`pkg.mod`), чтобы не
   переписать уже сохранённые `kb_edges`. Чужие языки получают префикс
   `ts:`, `rs:`, `cs:`. Двоеточие в имени Python-модуля не встречается.
2. **Демон не парсит чужие языки у себя.** Python по-прежнему читается
   `ast` в процессе ядра: проектный код не исполняется. Rust, C# и
   TypeScript печатают JSON версии 1 и завершаются. hostrun их запускает.
   В `sys.modules` демона нет `grimp`.
3. **Rust — `cargo metadata` плюс свой экстрактор на `syn`.** `cargo metadata`
   уже даёт рёбра крейтов. `cargo-modules` 0.28.0 печатает текст и Graphviz;
   запрос JSON открыт с 2024-12-02 и не закрыт
   (https://github.com/regexident/cargo-modules/issues/352). MSRV 1.98.
   Разбирать его дерево нельзя: следующий выпуск меняет отступы. Экстрактор
   `tools/rsgraph` на `syn` отдаёт `mod` и `use` внутри крейта. Неразрешённый
   `use` отбрасывается. Межкрейтовые рёбра остаётся у metadata.
4. **C# — опубликованный framework-dependent DLL, не Native AOT как условие
   выпуска.** Каталога `tools/csgraph` нет, а hostrun на каждый запуск зовёт
   `dotnet run` (восстановление и сборка). Боевой путь: `dotnet publish` без
   AOT и запуск через `dotnet exec`. Семантика: `inherits` и новое значение
   `implements`. Внедрение через конструктор и рёбра `call` не извлекаются:
   это эвристика, не факт компилятора. Слой Roslyn Workspaces под Native AOT
   не ставится. Спайк AOT допустим только на `Microsoft.CodeAnalysis` и
   `Microsoft.CodeAnalysis.CSharp`, без Workspaces, Scripting, `Emit` и
   загрузки анализаторов. Так же ограничил спайк Morphir от 2026-11-07:
   https://finos.github.io/morphir-dotnet/contributing/design/spikes/extension-model/roslyn-aot/.
   Провал спайка не блокирует узел: в артефакте лежит отчёт, выпуск идёт
   через DLL. Узел с `review_required`: человек видит, какой путь выпущен.
5. **TypeScript не скачивается в момент индексации.** Сейчас argv —
   `npx --yes dependency-cruiser@18.7.0`. `npx --yes` ходит в сеть и может
   принести другой tarball. В образе devtools лежит закреплённый бинарь 18.7.0.
   Нет бинаря — ошибка `CODEGRAPH_EXTRACTOR_FAILED`, не установка. Динамический
   `import()` остаётся ребром `imports`: так dependency-cruiser уже помечает
   его в своём JSON. Алиасы берутся из `tsconfig` самого репозитория, без
   обхода `node_modules`.
6. **`interface_hash` — хэш скелета, `body_hash` — хэш байтов файла.** Для
   Python скелет — уже существующий `python_skeleton`. Для остальных языков
   экстрактор добавляет в узел необязательное поле `symbols` (кортеж строк).
   Старые экстракторы без поля читаются как пустой кортеж: msgspec не требует
   его, версия протокола остаётся 1. Хэш интерфейса — SHA-256 канонического
   текста символов. Синтаксическая ошибка даёт пустой интерфейс и снимает
   исходящие рёбра этого файла; пустой хэш не считается «интерфейс не
   менялся». Пока `interface_hash` равен сохранённому, рёбра узла не
   переписываются, даже если `body_hash` новый.
7. **Контекст смотрит вперёд по импортам, радиус — назад.** LOD: модули,
   которые редактируемый файл использует. CTE радиуса, как в 0.1.3, идёт
   против стрелок. Смешивать их нельзя: агенту нужны контракты калли,
   а проверке Tier 2 — те, кто сломается.
8. **Полосы дистанции.** `d = 0` — срез целевого файла, как сейчас.
   `d = 1` — скелет или список `symbols`. `d = 2` и `d = 3` — одна строка
   `path kind symbols` на модуль. `d >= 4` — нет в пакете. Сортировка путей
   лексикографическая. При переполнении бюджета сначала выпадают строки
   `d = 3`, затем `d = 2`, затем самые длинные скелеты `d = 1`. Контракт
   узла, scope и хэши не режутся.
9. **Доля KV-кэша не является приёмкой.** Кэш провайдера — это побайтовый
   префикс запроса, который собирает сам CLI. Документация Claude: любое
   отличие байта до точки останова сбрасывает хвост
   (https://platform.claude.com/docs/en/build-with-claude/prompt-caching,
   https://code.claude.com/docs/en/prompt-caching). Ответ MCP попадает в
   историю как результат инструмента. Ядро гарантирует только свои байты:
   одинаковый интерфейс и одинаковый контракт дают одинаковый
   `direction_prefix`. Цель «90 %» в приёмку не ставится. Замер
   `cache_read_input_tokens` остаётся отчётом Tier 3, как в 0.1.3.
10. **Эхо — сравнение blake2b с `vault_files`, не окно 10 секунд.** Тот же
    дайджест, что `_digest` в `vault/writer.py`: blake2b, `digest_size=32`.
    Совпадение с `frontmatter_hash` и `body_hash` после рестарта — эхо, событие
    отбрасывается. Несовпадение — внешняя правка и прежний разбор frontmatter.
11. **Фокус Obsidian ядру неизвестен.** JSON Canvas 1.0 — файл с `x`, `y`,
    `width`, `height`, а не API редактора
    (https://github.com/obsidianmd/jsoncanvas/blob/main/spec/1.0.md).
    Публичного способа узнать, что человек держит заметку открытой, нет.
    `focus()` у canvas-узла — внутренний тип, не контракт
    (https://obsidian-typings.github.io/). Поэтому ядро не ждёт потери фокуса.
    Если байты вне секции `## Попытки` не совпали с последней записью ядра,
    файл не переписывается вообще, включая хирургическую строку попытки.
    Попытка остаётся в `node_attempts`. `pending_write` хранит отложенный
    текст. Следующая публикация пишет файл, когда посторонние байты снова
    совпали.
12. **Каталоги `app/`, `user/`, `tasks/` не создаются.** Заметки живут в
    `plans/<plan>/<KEY>.md`. Владелец поля задан `FIELD_OWNER`. Перенос
    сломает Canvas, который уже ссылается на `plans/<plan>/<KEY>.md`, и
    заметки существующих планов.
13. **Canvas: Кан по `depends_on` только среди L1, затем один проход
    барицентра.** L0 в слои не входит: направление L0 зависит от своих L1,
    и слой по этим рёбрам перевернёт карту. Группа L0 по-прежнему охватывает
    своих детей. Сохранённые `canvas_positions` побеждают вычисленные
    координаты. Цикл в грязных данных не роняет синхронизацию: оставшиеся
    узлы встают в слой 0 по ключу. Шаг X для новых позиций — 450 пикселей.
    Высота строки остаётся `_ROW = 240`. Цвета пресетов `"1"`…`"6"` не
    меняются: в Canvas это фиксированная палитра, а не произвольный CSS.
    Раскладка окна `ui/viewmodels/logic/plan_layout.py` — другой алгоритм и
    в этот узел не входит.
14. **Предпроверка покрывает патч, который прислали ядру.** CLI пишет
    worktree сам; отменить это без ломки агента нельзя. Это уже решение
    0.1.3, §2.9. Новый необязательный аргумент `patch` у `step_submit`:
    unified diff не длиннее 256 КиБ. Файлы вне `paths` — `SCOPE_VIOLATION`,
    worktree не трогается. Синтаксис и типы гоняются по копиям в каталоге
    предпроверки. Тесты по-прежнему идут по worktree после успешной
    проверки копий: частичное дерево не импортирует пакет. Провал тестов
    снимается уже существующим `step_reset`.
15. **Каталог предпроверки виден контейнеру, но это не новый bind всего
    дома.** Проверки исполняются `podman exec` (SEC-3). `$XDG_RUNTIME_DIR`
    в рекомендуемую изоляцию не смонтирован. Каталог —
    `$XDG_RUNTIME_DIR/aconsole/preflight/<node>/<attempt>/` на хосте. В
    контейнер на время одной проверки монтируется только он, в
    `/tmp/aconsole-preflight`, без дома, без сокета демона, без
    `aconsole.db`. Путь источника нормализуется и обязан остаться внутри
    каталога предпроверки. Нет контейнера — `GATE_RUNNER_UNAVAILABLE`, на
    хосте команда не запускается.
16. **FTS5 есть, sqlite-vec нет.** Запрос концепта с `MATCH` и `ORDER BY rank`
    — обычный FTS5: `rank` там является BM25, меньшее значение релевантнее.
    Виртуальной таблицы в ORM нет, поэтому запросы живут в одном новом
    модуле, и только он добавляется в `ALLOWED`. Токенизатор `unicode61`.
    Английский porter для русских заметок не включается. `sqlite-vec` в
    поставку CPython не входит, для него нужны эмбеддинги и модель. Это
    снова токены и RSS. В 0.1.4 векторного индекса нет.
17. **PRAGMA `mmap_size=268435456` и `wal_autocheckpoint=4000` не ставятся.**
    Отображённые страницы входят в RSS. Потолок ядра уже превышен и принят
    отдельным долгом. `wal_autocheckpoint` остаётся 1000, `journal_size_limit`
    остаётся 4 МиБ. Менять их можно только новым решением человека после
    замера.
18. **Память.** MEM-1 сторожит сценарий «ядро, 5 вкладок» сверху принятых
    175,81 МиБ. Допуск нового кода — 8 МиБ. Старый текст «120 МиБ» в
    квитанциях 0.1.3 не переписывается этим планом. Экстракторы в RSS ядра
    не входят: они чужие процессы.
19. **Схема MCP.** Необязательное поле `patch` у `step_submit` и поле
    `symbols` у узла графа — добавления. `API_VERSION` остаётся `1.5.0`,
    IPC остаётся 1.0. Возможность `preflight.v1` публикуется рядом с
    `hdag.v1`, когда GAT-1 умеет принимать патч. Старый клиент без поля
    работает как сейчас.
20. **Заморозка и роли прежние.** Этот документ готовит граф. На доску его
    ставит вкладка `mode=plan`. Вкладка `execute` получает `PLAN_ROLE` на

## 3. Протокол экстрактора

Версия JSON остаётся 1. К узлу добавляется необязательное поле:

```text
symbols: tuple[str, ...] = ()
```

Строка символа — стабильное объявление без тела: для Rust `pub fn name(args) -> ret`,
для C# сигнатура члена, для TypeScript экспорт из декларации модуля, если
dependency-cruiser её не даёт и её дописывает маленький разбор `export`
регулярным выражением нельзя. Для TypeScript в 0.1.4 достаточно рёбер
dependency-cruiser; `symbols` может быть пустым, и полоса `d = 1` тогда
является одной строкой пути и списка импортов. Пустой список честно
отличается от Python-скелета и не притворяется AST.

Идентификаторы:

| Язык | id узла | kind ребра в `kb_edges` |
|---|---|---|
| Python | `pkg.mod`, как сейчас | `imports` |
| TypeScript | `ts:` + путь POSIX | `imports` |
| Rust, модуль | `rs:<crate>/<module path>` | `imports` для `use` и `mod` |
| Rust, крейт | id из `cargo metadata`, с префиксом `rs-crate:` | `depends_on` |
| C# | `cs:` + путь документа, либо `cs:` + имя типа, если узел — тип | `inherits`, `implements` |

`implements` добавляется в `KbEdgeKind`. Колонка — VARCHAR через
`Enum(native_enum=False)`, отдельного CHECK в модели нет. Миграция схемы под
новое слово не нужна. Рёбра с `origin`, отличным от `codegraph`, не
удаляются при синхронизации графа. Это правило 0.1.3 сохраняется.

Слияние в `CodeGraphIndex._build`:

1. Собрать каждый включённый язык, чей маркер есть. Python — по
   `pyproject.toml` / `setup.py` / `setup.cfg`, через `scan_python`.
   TypeScript — по `package.json` или `tsconfig.json`. Rust — по
   `Cargo.toml`: сначала metadata, затем `rsgraph`. C# — по `*.sln` в корне
   либо по `*.csproj` в корне, один проект за запуск.
2. Ошибка одного языка не уничтожает остальные. В граф попадает пометка
   узла `kind=extractor-error` с путём маркера и текстом хвоста stderr
   (уже обрезан до 400 символов раннером). Индекс при этом не поднимает
   исключение на весь корень.
3. Повторный обход того же набора хэшей интерфейса не пишет рёбра (§2.6).
   TTL 300 с остаётся предохранителем полной пересборки, а не единственным
   ключом инвалидации.

## 4. Алгоритмы

### 4.1. Хэши файла

```text
body_hash = SHA-256(bytes файла)
interface_hash = SHA-256(текст скелета или символов в UTF-8)
```

Для Python текст — вывод `python_skeleton`. Пустая строка после `SyntaxError`
означает «интерфейса нет»: исходящие рёбра удаляются, кэш скелета этого
хэша не пополняется.

Инкремент в репозитории графа, в одной транзакции writer:

- новый id — вставка узла и его рёбер;
- тот же `interface_hash` — обновить `body_hash`, рёбра не трогать;
- другой `interface_hash` — заменить исходящие рёбра `origin=codegraph`;
- id исчез — удалить узел модульного графа.

### 4.2. Полосы LOD

Дистанция считается BFS вперёд: от редактируемого файла по ребрам
`imports` / `depends_on` / `inherits` / `implements`, глубина до 3, не больше
40 узлов. При ромбе остаётся меньшая дистанция. Обход на сохранённом графе,
рядом с существующим обратным CTE, с тем же правилом `UNION` вместо
`UNION ALL`.

Бюджет префикса — уже существующие 256 КиБ всего ответа шейпера. Обрезка
полос происходит до сериализации префикса. Порядок ключей JSON остаётся
`sort_keys`. В префиксе нет времени, ULID и `lease`.

Приёмка LOD-3: два тела с одним скелетом дают один и тот же
`direction_prefix` и один `prefix_sha256`. Смена сигнатуры меняет оба.

### 4.3. Canvas

Вход — узлы L1 и их `depends_on` на другие L1. Ребро L0 → L1 в раскладку
не идёт (`canvas.py` уже не рисует его как `blocks`).

```text
слой(u) = 0, если нет предшественников L1
слой(u) = 1 + max слой(v) по рёбрам v → u
```

Очередь Кана при равном входе сортируется по ключу, чтобы координаты не
плавали между запусками. Затем внутри слоя, начиная со слоя 1, узлы
сортируются по барицентру: среднее Y предшественников из предыдущего слоя,
при равенстве — ключ. Узлы слоя 0 остаются в порядке ключа. Новая позиция:
`x = слой * 450`, `y = индекс * 240`. Если для id есть строка в
`canvas_positions`, берётся она. Группа L0 считается по детям так же, как
сейчас. Группы в массиве `nodes` идут раньше файлов: в JSON Canvas первый
элемент рисуется ниже.

### 4.4. Эхо и конфликт

Публикация считает два blake2b, front и body, и пишет их в `vault_files`
в той же транзакции, что и снимок frontmatter. `EchoBook` остаётся быстрым
путём на 10 секунд.

Обработчик inotify:

1. Прочитать файл.
2. Если книга эха узнала байты — выйти.
3. Если оба дайджеста равны колонкам `vault_files` — выйти.
4. Иначе отдать frontmatter существующему `merge`.
5. Тело: если байты вне `## Попытки` отличаются от последней записи ядра,
   не вызывать ни полную перезапись, ни `update_attempt`. Отложенный
   текст положить в `pending_write`.

### 4.5. FTS5

Миграция `0012_notes_fts` (номер проверить по голове `migrations/versions`:
последняя сейчас `0011_node_attempts`):

```sql
CREATE VIRTUAL TABLE note_fts USING fts5(
    title,
    body,
    note_ref UNINDEXED,
    tokenize = 'unicode61'
);
```

Строка переписывается в той же транзакции, что сохранение факта или
публикация заметки: `DELETE` по `note_ref`, затем `INSERT`. Запрос:

```sql
SELECT note_ref, bm25(note_fts) AS rank
FROM note_fts
WHERE note_fts MATCH :query
ORDER BY rank
LIMIT :limit;
```

`bm25()` выбран явно, а не голый столбец `rank`: знак и имя столбца путают
читателя, функция в FTS5 определена однозначно. Запрос живёт в
`infrastructure/persistence/search.py`. Этот файл — вторая запись `ALLOWED`
в `tools/check_no_raw_sql.py` после `engine.py`. Больше файлов туда не
добавляется.

`ctx_get` при пустом запросе работает как сейчас (фильтр по путям узла).
При непустом запросе порядок задаёт `bm25`, хвост по-прежнему режется
`max_items`. Факт, которого нет в FTS (старая строка до переиндексации),
добирается прежней подстрокой и встаёт после ранжированных.

Запрос FTS с синтаксисом операторов (`AND`, кавычки, `*`) передаётся как
есть. Ошибка разбора MATCH возвращает пустой список и код не поднимает
500: агентский запрос не должен ронять `ctx_get`. В тест входит и
обычное слово, и заведомо кривая строка.

На этой машине системный CPython видит SQLite 3.53.1 с `ENABLE_FTS5`
(`PRAGMA compile_options`, 2026-11-16). Интерпретатора `.venv-core` в
рабочей копии нет, поэтому FND-1 всё равно проверяет тот Python, которым
запускается демон.

### 4.6. Предпроверка

`step_submit` принимает `patch: str | None`. Пустое значение — нынешнее
поведение. Непустое:

1. Размер ≤ 256 КиБ, формат unified diff, пути внутри `paths` узла.
   Иначе `SCOPE_VIOLATION` или `NODE_CONTRACT`, worktree тих.
2. Копии затронутых файлов пишутся в каталог предпроверки. Исходный
   worktree на этом шаге не меняется.
3. Контейнер получает mount только этого каталога. Ступени ruff и
   тайпчекера профиля L0 читают копии. Аргументы по-прежнему только из
   замороженного профиля.
4. Провал: каталог удаляется, worktree не менялся, агенту уходит
   `compact_verdict` до 500 символов, попытка расходуется по правилам Tier 1.
5. Успех синтаксиса и типов: файлы копируются в worktree, дальше обычный
   точечный тест Tier 1. Провал теста не откатывает сам себя в GAT:
   откат — `step_reset` к последнему зелёному снимку.

Повтор того же `state_hash` по-прежнему не запускает инструменты: это
`verification_gate_cache`.

## 8. Загрузка на доску

Вкладка `execute` этот граф создать не может: `plan_create`, `plan_save`
и `plan_delete` для неё скрыты, прямой вызов отвечает `PLAN_ROLE`.
Загрузка — из вкладки `mode=plan` (Claude или Codex) одним `plan_save`:
заголовок, цель и все узлы §6 в одном `nodes`. Повтор того же заголовка
без `plan_id` возвращает тот же план. `plan_id` меняет заголовок или
заменяет набор узлов, пока план в фазе `draft`. `plan_delete` снимает
план, если ни один узел не в аренде. IPC-двойники тех же операций —
`plan/save` и `plan/delete` (API 1.6.0).

Заголовок: `0.1.4 — Индекс, LOD и vault`.

Цель (её и передать в `goal`):

> Сделать дельту концепции 0.1.4 поверх закрытого plan-636. Полиглотный
> индекс без сети и без парсеров в процессе демона; body_hash и
> interface_hash; LOD по прямой дистанции импорта; долговечное эхо blake2b
> и отказ затирать чужое тело заметки; Canvas L1 слоями Кана и барицентром;
> патч step_submit проверяется до копирования в worktree; FTS5 BM25 в
> ctx_get. Без sqlite-vec, без mmap 256 МиБ, без cargo-modules как
> контракта, без Native AOT как условия C#, без каталогов app/user/tasks,
> без волн OpenCode/Cursor/Grok/LiteLLM. Источник истины:
> plans/0.1.4-index.md. L0 закрывает человек.

Узлы L0: `level=0`, `pipeline=false`, `depends_on` — их L1 из §6.
Узлы L1: `level=1`, `pipeline=true`, `parent` — ключ направления.
`objective` каждого узла на доске — абзац «Сделать» и «Приёмка» из §6,
плюс строка «Подробно: plans/0.1.4-index.md». Поле длиннее 2000 символов
не проходит схему `NodeIn`. `test_cmd` — команда из §6. `paths` — список
путей из §6. У IDX-4 `review_required=true`.

Исправление 0.1.3(б): у каждого L0 нужен **полный** `gate_profile.micro`,
а не только `direction` и `environment`. Все пять команд обязательны;
без них подготовка и заморозка возвращают `NODE_CONTRACT` с именем поля.
Пример для devtools этого репозитория (пути интерпретатора и доступность
инструментов проверяются до заморозки):

```json
{
  "micro": {
    "format": [".venv-core/bin/python", "-m", "ruff", "format"],
    "fix": [".venv-core/bin/python", "-m", "ruff", "check", "--fix"],
    "lint": [".venv-core/bin/python", "-m", "ruff", "check"],
    "types": [".venv-core/bin/python", "-m", "basedpyright"],
    "tests": [".venv-core/bin/python", "-m", "pytest", "-q"]
  }
}
```

К этому объекту добавляются `direction` с проверкой соответствующего L0 и
`environment`. Пример не заполняет их автоматически. Для старого frozen-плана
с ошибочным профилем повторная заморозка и снятие `blocked` ничего не исправляют:
требуется явная корректировка контракта через планирование. Прямые записи в БД
и автоматическая замена команд при запуске не используются.

Для исправления старого frozen-плана предусмотрен `plan_save` с `plan_id`,
прежними `title` и `goal`, без `nodes`, и с `repair_gate_profiles` — объектом
`{ "IDX-0": полный_профиль, ... }` по ключам L0. IPC `plan/save` принимает
то же поле. Требуется передать все ошибочные профили; действующий корректный
профиль менять таким способом нельзя. Не должно быть аренд, начатых pipeline-попыток
или узлов вне `pending`/`blocked`. Состав графа, ID, fences и история сохраняются,
хеши контрактов пересчитываются, решение записывается в журнал атомарно с планом.
План остаётся frozen, повторная заморозка не нужна. Повтор той же правки идемпотентен.

При первоначальной загрузке `plan_ready` должен был вернуть ровно IDX-1, VLT-1, VLT-3,
GAT-1, FND-1, MEM-1. Если в списке есть L0, уровни сохранены неверно.

## 9. Риски

| Риск | Мера |
|---|---|
| SDK .NET в devtools не тянет Roslyn Workspaces | IDX-4 останавливается отчётом. Сеть и `dotnet run` не становятся запасным путём |
| `syn` не разрешает `use` с переименованием | Ребро не создаётся. Ложное ребро хуже дырки: Tier 3 и `test_cmd` узла остаются |
| dependency-cruiser не видит `require` старого JS | Для репозитория с `tsconfig` это фиксируется в отчёте узла, вид ребра не выдумывается |
| FTS5 не собран в `libsqlite` демона | Узел FND-1 первым делом проверяет `PRAGMA compile_options`. Нет `ENABLE_FTS5` — узел `blocked`, а не тихий откат на `LIKE` в проде |
| Mount предпроверки расширяет видимость контейнера | Источник — один каталог, проверка `..` в GAT-1, режим не добавляет дом и сокет |
| Копирование после зелёного синтаксиса падает на тесте | Это прежний Tier 1 плюс `step_reset`. Отдельного отката «до диска» для тестов нет, §2.14 |
| Кан на грязном цикле | Узлы цикла остаются в слое 0, синхронизация vault не падает |
| Рост RSS от новых колонок и FTS | MEM-1. Индекс FTS пишется писателем, не отдельным процессом в адресном пространстве сверх транзакции |
| Исполнитель дробит узел | Заморозка 0.1.3. Новый узел — только change request человека |
