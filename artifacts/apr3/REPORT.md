# APR-3 — уведомления о запросах другой вкладки

База: `f15498a4`. Узел `plan-1/node-27`.

## Проблема и изменение

Gio.Notification, эпизоды, отзыв и действие перехода уже реализованы. Однако
ApprovalAlerts подавлял все уведомления при активном окне: запрос другой
вкладки оставался без уведомления, хотя пользователь его не видел.

Теперь MainWindow передаёт выбранную вкладку. При активном окне подавляется
только её запрос; другие вкладки уведомляют один раз на эпизод. Переход к
вкладке отзывает уведомление и не создаёт дубль при следующем уходе. При
неактивном окне уведомления сохраняются для всех вкладок. Без выбранной
вкладки запросы не считаются просмотренными. До map уведомления не публикуются.

Сохранены отзыв при решении/закрытии окна, отдельные эпизоды вкладок,
отсутствие текста команды в уведомлении и Gio action перехода к нужному tab.
Публикация уведомления не принимает решение и не перехватывает фокус.

## Проверки

На отдельном Xvfb, текущий worktree:

- `tests/gui/front/test_approval_alerts.py` и
  `tests/gui/front/test_approval_panel.py`: **28 passed**, 9.23 секунды, exit 0.
- Три новые регрессии: запрос фоновой вкладки при активном окне, отзыв после
  переключения без повторного эпизода и активное окно без выбранной вкладки.
- Интеграционный MainWindow/Gio-action тест дополнен сценарием с активным
  окном, запросом другой вкладки, отсутствием дубля и отзывом по клику.
- Ruff изменённых Python-файлов и `git diff --check`: успешно.

В тестах перехватываются send_notification/withdraw_notification: проверяется
Gio.Notification и маршрутизация приложения, реальные сообщения на рабочий
стол пользователя не отправляются. Нативный desktop notification daemon
не тестировался. Одна прежняя deprecation warning gi.events не мешает прогону.

Xvfb распакован в приватный временный каталог из apt-пакета без установки
в систему. Используются собственный Xauthority и `-nolisten tcp`. Сервер
и временные файлы очищаются. Runner сохранён в `xvfb-runner.txt`.

## Surprises & Discoveries — визуальная проверка

Применён gtk-screenshot-review. Штатный hostrun привязан к основному checkout,
поэтому ui_snapshot.py текущей копии запущен напрямую внутри отдельного Xvfb;
`--fake waiting` создаёт собственный fake core без постоянного демона.

Просмотрены три снимка `ui/waiting-{light,dark,narrow}.png`, запрошенные размеры
1280×800 и 700×800. Кнопки решения и предупреждение видны, ключи переведены,
на узком экране sidebar сворачивается, светлых участков в тёмной теме нет.
Изменений геометрии карточки этот коммит не вносит. `docs/design/DESIGN.md`
в checkout отсутствует: буквальное сравнение с макетом не заявляется.
Снимки не означают пользовательскую приёмку APR-1 и не закрывают проверку Orca.

Установленное приложение и работающие агенты не перезапускались.
