# SEC-4 — запрет поддельного review и самоодобрения

База: `1795dd4`. Узел `plan-1/node-10`.

## Граница доверия и решение

Отчёт gate, task bases и review JSON находятся в каталогах, доступных агенту.
Даже корректный digest связывает два изменяемых агентом файла, а не доказывает
независимую приёмку. Агент может изменить и выполняемый phase_gate, вернув 0.
Смена каталога state или второго контейнера при общем writable HOME этого
не исправляет. Поэтому принято техническое решение fail-closed:

- `gate-review approve` запрещён всем агентам, включая Claude, независимо
  от более широкой local policy. Отказ есть и в builder, и в runtime для
  старого непосредственно созданного review plan.
- `gate-review inspect` сохранён для чтения конкретного diff, без создания
  approval. Ответ inspection не является доверенным одобрением.
- Удалена логика повышения failed gate до PASS по review-файлам и переписывания
  канонического отчёта. Отчёты остаются диагностическими, их формат не меняется.
- Task и audit gate запускаются как прежде в devtools, но даже child exit 0
  возвращается как exit 1 с сообщением `UNVERIFIED`, требующим независимой
  приёмки. Ненулевые ошибки запуска и проверок сохраняются.

Это отключение доверенного PASS, а не реализация независимого verifier.
Для восстановления функциональности добавлен **GATE-1 / node-195** с зависимостью
от SEC-4 и SEC-7: неизменяемый проверяющий, недоступное агентам состояние,
независимый субъект approval и положительный сценарий приёмки. До него
агентский hostrun gate не может служить успешным release gate.

## Проверки

Полный `tests/hostrun` текущего worktree в devtools: **208 passed, 1 skipped**,
21.57 секунды, exit 0. Пропуск прежний: отсутствуют linked `docs/` со списками
клиентов (`test_allowlist.py:50`).

Проверены forged approvals вне checkout, повтор review, копирование repository,
изменение diff, испорченные и устаревшие JSON, сохранность сырых отчётов,
поддельный PASS и нулевой код изменяемого gate (task и audit), HTTP self-approval
от четырёх агентов при принудительно расширенной policy, обход builder старым
runtime plan, а также read-only inspection. Старые позитивные тесты promotion
заменены отрицательными регрессиями; проверки испорченных отчётов сохранены.

`compileall`, синтаксический тест Python 3.12 и `git diff --check` проходят.
Ruff в явно указанных обычно исключённых файлах: actions 8 → 8,
server 35 → 28, test_gate_reviews 5 → 5 прежних замечаний.
Сравнение по (код, сообщение) не обнаружило новых замечаний.

## Активация

Изменения только в рабочей ветке; действующая policy и service не менялись,
hostrun не перезапускался. После интеграции требуется штатная активация.
Защита самого hostrun/state от записи через монтирования остаётся в SEC-7;
этот коммит не заявляет защиту от замены кода доверенного сервиса на диске.
