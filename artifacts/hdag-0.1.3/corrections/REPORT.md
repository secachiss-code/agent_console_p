## 1. Память

Добавлен `tools/profile_hdag_memory.py`: отдельные процессы UI/core,
изолированная БД и сокет, циклы 0 → 1 → 5 → 0 вкладок, RSS/PSS/private memory,
идентичность процесса, счётчики объектов и SHA-256 фактически загруженного src.
Core использует настоящий Daemon/Writer/SQLite с неактивными восстановленными
вкладками; UI — настоящие виджеты и отдельный fake core. Это компонентный
профиль, не приёмка работающих CLI-агентов.

Найдены и исправлены удержания TerminalPage, TabRow и ApprovalCard: обработчики
сигналов освобождаются, clipboard/search разрывают обратные ссылки, строки
отключаются и отсоединяются при unbind. При повторном bind создаётся новая
строка; это небольшой расход на создание виджетов вместо накопления старых.
Настройки renderer и лимиты памяти не менялись.

Контролируемое сравнение: одни библиотеки host GTK, X11, default renderer,
три одинаковых цикла; исходные UI-файлы для before взяты из HEAD во временный
каталог. После последнего закрытия:

PSS не подставляется вместо RSS для получения PASS.

## 2. Достоверность UI-метрик

UI регистрируется после IPC-handshake по SO_PEERCRED. PID из initialize или CLI
не регистрирует процесс. При отключении регистрация снимается с учётом нескольких
соединений одного процесса. Идентичность включает PID, starttime из `/proc/stat`
и boot_id. Измерение проверяет её до и после чтения smaps_rollup.

Произвольный PID, PID уже отключённого UI и повторное использование PID
не подходят для проверки. Аудит сохраняет идентичность UI; восстановление
по прежнему аудиту требует её совпадения. Явный повтор gate в новом UI обновляет
аудит даже при повторном использовании зелёной квитанции без запуска тестов.

## 3. Окружение квитанций

Реализован выбранный вариант с неизменяемым окружением, а не с кэшем версий
инструментов. В замороженном профиле указываются отдельный контейнер и ID образа;
проверяются read-only rootfs/checkout, mounts и отсутствие внешних venv.
Замена окружения во время проверки не даёт зелёного результата. В аудит
добавлены ID образа и SHA-256 окружения. Подробная эксплуатация —
[ENVIRONMENT.md](ENVIRONMENT.md).

Новый образ в этой среде не подготовлен. Работающее изменяемое окружение
не объявлено неизменяемым: Tier 3 должен отказать до подготовки sealed-контейнера.

## 5. Критичные проверки

Обязательная часть выполнена: отрицательная матрица процессов/окружения,
отказ старой квитанции при смене окружения, смена во время проверки,
повтор без повторного исполнения, durable аудит/restart и запрет закрытия
без актуальной квитанции. Runner проверяет и исполняет конкретный container ID;
это отдельно проверено настоящим subprocess с записывающим Podman-адаптером.

## Проверка UI

Применён навык gtk-screenshot-review. hostrun отсутствует в текущем окружении;
host-spawn не даёт рабочего запуска. Использованы уже установленные host GTK
через host dynamic loader и отдельный Broadway backend без ввода в desktop.
Иконки загружены через host pixbuf cache; пакеты не устанавливались.

Light/dark/narrow снимки приложены. Broadway ограничил широкий viewport до
1024×768, узкий — 700×768; это фактические размеры, не заявленные 1280×800.
Просмотрены подписи, меню, кнопки approvals, список и терминал: нет новых
обрезанных действий, сырых translation keys или светлых пятен в dark.
docs/design/DESIGN.md отсутствует, сравнение с ним не заявляется.
