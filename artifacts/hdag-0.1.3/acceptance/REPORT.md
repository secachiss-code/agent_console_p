## Исправленная ревизия плана

Первый план обнаружил ошибку приёмочного контракта: ACC-2 сам должен исчерпать
все четыре попытки и завершиться отменой, однако ACC-4 зависит от его done.
Отмена закономерно не разблокирует зависимые узлы. Первый план сохранён:
ACC-1/3 done, ACC-2 cancelled после проверки, ACC-4 blocked с объяснением.

Создан отдельный план `plan-7`, **до первого claim замороженный** через human IPC:
[revision-2-plan.json](revision-2-plan.json). В нём ACC-2 проверяет неизменные
SHA-256 журналов исчерпанной фикстуры и ATTEMPTS_EXHAUSTED до/после restart.
Сам негативный сценарий остаётся в первом плане. Все четыре L1 второго плана
проходят настоящие micro/blast и завершаются done. Новые положительные узлы
исполнял детерминированный MCP HTTP драйвер; повторного запуска модели для них
не заявляется. Первый живой CLI остаётся самостоятельным доказательством.
В каждом плане осталось по **5 вершин**, L2-вершины не создавались.

ACC-4 проверяет подготовку измерений; числовые бюджеты проверяет L0 после
завершения дочерних узлов. Требовать от L1 заранее зелёный L0 было бы циклическим
условием. ACC-0 второго плана через штатный API помечен blocked по факту RSS.
API правки зависимостей frozen-плана не расширялся.

## Окружение и воспроизведение

Обнаружен рабочий host transport: D-Bus socket доступен из агента по
`/run/host/run/user/1000/bus`; прежний путь `/run/user/1000/bus` был обычным файлом.
На host доступны Podman 4.9.3 и conmon. Предыдущий вывод об отсутствии conmon
не был свойством host и здесь исправлен.

Базовый Debian image уже был локальным. Образы собраны без pull, сетевой сборки
и установки пакетов: снимок существующих venv/Python/Git/Codex, затем публичные
CA и CLI helper. Точные IDs и проверенные mounts — [runtime.json](runtime.json).
Gate image: `f4147a4165dbe6b85c65b0c7b0de4858bc9114466edabf2132f333861102eb70`.
Gate container имеет read-only rootfs, read-only bind checkout, tmpfs /tmp,/run,
cap-drop ALL, network none; отдельный executor имеет RW bind только фикстуры.
CLI helper и alias python3 нужны executor; его дополнительный образ не меняет
зафиксированный gate image. Состав исходного software snapshot —
[software-manifest.json](software-manifest.json); build-рецепты — `build/`.
Auth и MCP bearer содержались только в приватных файлах/RO mounts; их нет в
образах или опубликованных артефактах. Проверено сканированием действительных
секретных значений без вывода этих значений.

Инструменты: `prepare_hdag_environment.py` готовит новый build context;
`hdag_acceptance.py prepare/pin/serve` создаёт отдельный стенд;
`exercise_hdag.py retries/review/identity` выполняет отрицательные сценарии;
`observe_hdag_ui.py` держит настоящую компонентную GTK-нагрузку;
`revise_hdag_acceptance.py` выполняет добавочную ревизию. Сценарии изменяют только
одноразовый fixture repository. Повторять их следует на новом стенде, поскольку
исчерпанные попытки и frozen-контракты намеренно не сбрасываются.
