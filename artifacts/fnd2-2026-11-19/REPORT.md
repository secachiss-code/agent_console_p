# FND-2 — ранжирование контекста по BM25

Узел `node-920`, план `plan-900`. Реализация `aaf068f9`.

Непустой `ctx_get` передаёт запрос SQLite FTS5 и возвращает факты
текущего проекта в порядке BM25. При равном балле порядок задаёт ID.
Выборка читается до `max_items + 1`, чтобы определить `truncated`.
Совпадения среди старых фактов, у которых ещё нет строки в индексе,
добавляются по прежнему поиску подстроки. Пустой запрос использует фильтр
по путям узла. Ошибка синтаксиса MATCH возвращает пустой список.

Для подключения существующего Writer в контракт FND-2 добавлены порт
хранилища знаний и его SQLite-адаптер. Порт добавлен также в область
FND-0. Ремонт выполнен штатным `plan/save` с прежними хэшами. Первая
попытка отменена до проверки, вторая использовала обновлённый контракт
`d6b3f6bc0b509a53e6434b764c1b45e5a2f1d889f36226acf965e74825a37c3e`.

Локально 44 теста прошли. Ruff, basedpyright для пяти файлов и
`tools/check_no_raw_sql.py` прошли. В тестовом файле уточнены типы
существующих проверок, чтобы он проходил scoped basedpyright.

Micro прошёл 5 команд и 24 теста. Blast прошёл обе команды,
21 тест узла и 339 зависимых. Квитанции записаны для одного state hash
`541a3cfd140b1f83678a79c8888cc4e8181db42f8aafdb41221b58858b4343ab`.
MCP-запрос на Blast достиг лимита транспорта в 60 секунд. Ядро завершило
проверку и сохранило результат; повторный запуск не потребовался.
После чтения квитанций штатный `node_update done` принят.
На момент завершения FND-2 на доске 15 из 23 узлов `done`.
