# PERF-7: bounded title requisition experiment

Base: `2e82c5609db3a1939a48af0e162b098ab5307379`.
The final commit contains evidence only; product, tests and tools equal the base.
The 10,000-row, four-second workload and all performance assertions are unchanged.

## Hypothesis and result

The new native baseline again fails the 17.5 ms median requirement. Its separate
diagnostic profile records 3,838 `_show_node` calls (0.368 s cumulative), including
0.173 s in `format_date`. These figures span loading and scrolling and include
profiling overhead; they are not a per-frame budget or acceptance measurement.

Tested whether changing a recycled title's natural width causes avoidable native
measurement work. The experimental patch adds `max_width_chars=18` beside the
existing `width_chars=18`, keeping expansion and ellipsizing. The exact rejected
patch is saved in `bounded-title-trial.patch`; it applies to the pinned base.

| Diagnostic run | Median | Frames / 4 s | RSS (entry) | Load before |
| --- | ---: | ---: | ---: | ---: |
| Base, profile + phases | 33.4 ms | 114 | 269 (250) MiB | 2.90 |
| Bounded title, phases | 33.5 ms | 118 | 269 (250) MiB | 3.59 |

Both use the accelerated Intel ADL-N desktop, GTK's `GskNglRenderer` and the
normal test accessibility backend. Phase observations after loading, while
scrolling, are recorded below. Boundaries include native handlers and cannot
identify individual GTK functions. Pairwise medians need not sum to frame time.

| Wall-time interval | Base | Bounded title |
| --- | ---: | ---: |
| before-paint → end of update | 12.58 ms | 12.22 ms |
| end of update → end of layout | 4.97 ms | 5.35 ms |
| end of layout → end of paint | 5.76 ms | 6.35 ms |

No meaningful improvement was observed. Instrumentation differs between these
two diagnostic runs and ambient load was not controlled, so these observations
are not a statistical regression estimate. The hypothesis did not produce a
change worth retaining; the product edit was reverted. Neither diagnostic run
passes the original assertion.

The trial's isolated suite gives **4 passed, 1 failed**: narrow layout, recycled
tooltip, deferred binding and graph redraw tests pass; only the scale assertion
fails. Ruff and strict basedpyright pass for the trial view. No full suite is
claimed. The existing fixture deliberately uses `/usr/bin/false` for Podman;
its repeated ContainerError diagnostics are present in the raw logs and did
not prevent the scale workload from completing.

Final pinned-base run without optional profiling or phase recording: **1 passed,
1 failed**, median **33.4 ms**, 117 frames / 4 s, p95 49.4 ms, worst 50.5 ms,
RSS 269 MiB (entry 250 MiB). The established observer tick and GC callbacks remain.
The failed assertion is still the unchanged 17.5 ms median requirement. No full
suite was repeated after this failure because no product change was retained.

## Surprises & Discoveries

- Bounding the title requisition did not improve the observed frame cadence.
- GPU acceleration remains available; an unavailable GPU is not the blocker.
- Consulted `gtk-screenshot-review`. No view/style/layout change is retained,
  and no new screenshot review or mockup conformance is claimed. Existing
  screenshots do not validate the rejected prototype.

afterward. The other two commands use unchanged product code. Raw GL reports,
JSONL observations, JUnit XML, the diagnostic profile and its text summary are
preserved alongside this report. Machine-readable source bindings, final
results without optional profiling/phases and evidence digests are in `resume-validation.json`.

PERF-7 remains **failed**. This experiment rules out a small width hint as the
next retained optimization on this workload; it does not establish a root cause
or finish performance acceptance. A substantive reduction in native list
update/layout/paint cost, with keyboard, selection, accessibility and visual
behavior preserved, is still required. No renderer setting, benchmark assertion,
security gate, runtime installation, routing or release status changed.
