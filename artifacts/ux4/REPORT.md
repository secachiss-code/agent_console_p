# UX-4 — понятный первый запуск

База: `1436f06b`, узел `plan-1/node-42`.

## Изменения

Ошибка подключения к ядру показывает причину и путь к core.log прямо в окне,
рядом с повтором запуска и копированием диагностики.

Добавлены русские и английские пояснения проверки изоляции контейнеров.
Убрана устаревшая рекомендация подключать домашнюю папку: мастер направляет
к разделу Container isolation в README и предлагает проверить mounts.
Если контейнеров нет, текст объясняет следующий шаг и отличает справочную
команду podman create --help от команды создания контейнера.

Проверка уведомлений теперь различает отсутствие notify-send и сеанса D-Bus:
предлагает установку libnotify-bin только в первом случае, диагностику
systemctl --user status dbus.service — во втором.

Существующие сценарии повторного запуска, копирования команд, завершения
мастера и его повторного открытия из настроек сохранены.

light, dark и narrow; основной размер 1280×800, узкий 700×800.
Это настоящие GTK-виджеты текущего worktree с FakeCore и контролируемыми

последний запускается Python из host .venv-ui и временно извлекает Xvfb
из deb без установки пакета в систему.

Startup: причина, журнал и обе кнопки читаемы в светлой/тёмной теме
и узком окне; обрезания нет. Setup: причины, команды и кнопки видны;
длинные пояснения переносятся. Первый сценарий съёмки переопределял тему
слишком рано: настройки приложения затем возвращали тёмную тему.
Сценарий исправлен: settings/get возвращает выбранную тему, анимации
отключены. Повторно получены и просмотрены все варианты мастера: светлая
и тёмная темы различаются, узкое окно не обрезает текст и действия.
Старый файл снимка удаляется перед запуском, ошибка снимка повторяется
на следующем кадре; прежний файл больше не может скрыть неудачный захват.
Для захвата мастера требуется after-paint; прямой таймер до отрисовки
давал snapshot produced no node. docs/design/DESIGN.md отсутствует,
сопоставление с этим макетом не заявляется.
