# Готовность Tier 3 для AConsole 0.1.4

Проверено 2026-11-19 и 2026-11-20 для `plan-900`. Базовый checkout `0bf2f5cc` сравнивался
с исходниками поправки профиля Tier 3 из `92e9dbc3`. На доске 17 завершённых узлов
L1 и шесть открытых направлений L0.

## Поправка профиля

Нативный `plan/save` принимает полные профили через `repair_gate_profiles`
с прежними `plan_id`, `title` и `goal`. После закрытия L1 этот запрос
может заменить `direction` и `environment` в открытых L0 с нулевым
digest. Сохранение увеличивает ревизию, пересчитывает хэши изменённых L0
и записывает прежний и новый хэши конфигурации gate в журнал.
Тест с перезапуском ядра проверил сохранность L1, его контракта,
прошедшей попытки и квитанции Blast. Повтор запроса идемпотентен.

Целевой прогон дал 131 passed. Ruff, basedpyright для изменённых
исходников, проверка слоёв и проверка сырого SQL прошли.

## Повтор на итоговом образе

Тест мастера настройки теперь ждёт открытия диалога, закрывает его действием
«Позже» и повторно открывает перед завершением. Проверка подтверждает, что
первое действие оставляет `setup_completed=false` и только завершение отправляет
одно обновление настроек. В libadwaita 1.5 закрытие во время анимации открытия
может не сработать, поэтому тест даёт анимации завершиться перед действием.
Тест окна отслеживает `git/state` и `git/watch` после `unrealize` и `realize`.
События фокуса GTK могут вызывать `tab/focus` в этот же момент.

Эталоны DES3 пересняты в светлой и тёмной темах при 1280 px и в светлой
при 700 px. По сравнению с исходными эталонами в интерфейсе уже были видны
фаза плана и кнопка заморозки H-DAG, а карточка плана и состояние заблокированного
узла изменились. В узком кадре у графа видна только часть последнего столбца,
доступного горизонтальной прокруткой. Текст и кнопки карточки согласования
помещаются. Тёмные кадры проверены на светлые участки. GTK 4.18.6 и libadwaita
1.7.6 в sealed-образе меняют высоту некоторых элементов и оттенок кнопки отказа.
Для них добавлены отдельные эталоны, для GTK 4.14.5 и libadwaita 1.5.0 обновлены
основные. В обеих средах использовались Cairo, X11 и DejaVu Sans 10. Порог
сравнения остаётся 0,1% каналов с разницей больше 8/255.

На хосте в отдельном X11 все 25 тестов трёх изменённых файлов прошли.
Ruff, проверка сырого SQL и все шесть контрактов слоёв прошли.
Строгий `basedpyright` для этих файлов выдал те же 55 диагностик,
что на базовом `a4737461`.

В итоговом sealed-образе набор `tests/gui tests/ui tests/smoke` дал
**553 passed, 1 skipped** за 260,34 с. Пропущена проверка таблицы контрастности,
привязанная к цветам libadwaita 1.5. На хосте с этой версией она прошла.
Команда использовала `.venv-ui/bin/python` и Xvfb с X11, Cairo,
`GTK_A11Y=test` и экраном 1280×800×24.

Сбор полного набора ядра в итоговом образе нашёл 2744 теста. Одна команда
достигла лимита Tier 3 в 900 с. К этому моменту в логе было 2179 результатов,
из них 2164 passed, 12 skipped и 3 failed. Последние 1205 тестов запущены
отдельной командой из того же образа. Она дала **1197 passed, 6 skipped,
2 failed** за 472,74 с. До начала второй части (`test_mcp_core4_http.py`)
было 1527 passed и 12 skipped. Вместе эти два участка покрыли весь набор.

Два сбоя ядра пришлись на измерения производительности SQLite в
`test_persistence_b.py`. Третий повторился отдельно в `test_sidecar.py`.
Тестовый Python напечатал предупреждение о недоступном пути из `.pth` в PTY,
где тест ожидал `HELLO`. Для этого дочернего процесса добавлен `-S`, чтобы
его вывод зависел только от проверяемой последовательности. В итоговом
образе все 12 тестов модуля `test_sidecar.py` прошли.

Оба измерения SQLite прошли во второй части и при отдельном запуске
всего модуля `test_persistence_b.py` после завершения большого прогона.
Во второй части повторился сбой исходной PTY-фикстуры и упал замер Git
на девяти рабочих деревьях с 20 000 файлов. Медиана `git/state` составила
630 мс при лимите 400 мс. Отдельный повтор дал 620 мс в sealed-образе
и 441 мс на хосте. Проверка конфликта в том же модуле прошла.

В диагностическом прогоне с измерением фаз медиана полного `git/state`
составила 598 мс, из них медиана этапа `git status` по рабочим деревьям
составила 331 мс. В диагностике с `core.preloadIndex=false` эти значения
составили 548 и 260 мс. В этих диагностических прогонах использовалась
реализация Git из `7451c9e7`.

Последующая поправка распределяет чтение статуса и истории каждого рабочего
дерева по пулу из четырёх потоков и сохраняет порядок результата. Сведения
о сессиях считываются в потоке, вызвавшем `git/state`. При просмотре нескольких
рабочих деревьев `git status` получает `core.preloadIndex=false`, чтобы
внутренние потоки Git не конкурировали с параллельными сканированиями.
Порог 400 мс сохранён. Оба теста `test_git_scale.py` прошли дважды на
sealed-образе. Прогон с профилированием показал медиану **392 мс**.
Проверки Git, подмодулей, рабочих сессий и восстановления дали **155 passed**.
Ruff, basedpyright для изменённых модулей и проверка слоёв прошли.

## Условия приёмки на живом проекте

Зарегистрированный checkout проекта находился на `7451c9e7`. Он содержит
локальные `.venv`, `.venv-core` и `.venv-ui`, которые проверка sealed-среды
отклоняет. В снимке живого AConsole были две активные вкладки проекта.
Ядро занимало 240,56 МиБ RSS, интерфейс — 154,73 МиБ RSS. Пороги Tier 3
составляют 120 и 150 МиБ соответственно при минимум пяти вкладках.
Предыдущий контрольный замер ядра для MEM-1 составил 173,125 МиБ.
Работа по снижению RSS отложена в `TD-HDG-MEM-1`.

Поправка профилей проверена на отдельном экземпляре ядра. Для живого плана
ещё нужны интеграция исходников и проходной запуск через `plan/directionGate`,
чтобы применить решение о приёмке шести направлений.

Локальный `main` зарегистрированного checkout по-прежнему на `7451c9e7`.
Чтение живого снимка из контейнера вернуло `ROLE_FORBIDDEN`. Повтор с хоста
подтвердил **четыре активные вкладки**, **208,32 МиБ RSS ядра** и состояние
плана frozen с 17 из 23 закрытых узлов. Для интерфейса выше указан предыдущий замер.

Пользователь подтвердил приёмку всех шести направлений в решении `kb-970`.
Штатный `plan/setNodeStatus` вернул `GATE_RECEIPT_REQUIRED` для каждого L0.
По отдельному указанию пользователя `MEM-0` закрыта в статусе `cancelled`,
превышение бюджета памяти закреплено в `TD-HDG-MEM-1` решением `kb-973`.
Состояние доски после перехода — 17 выполненных, одна отменённая и пять открытых вершин.
