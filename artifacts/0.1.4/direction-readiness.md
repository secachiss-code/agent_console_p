# Готовность Tier 3 для AConsole 0.1.4

Проверено 2026-11-19 и 2026-11-20 для `plan-900`. Базовый checkout `0bf2f5cc` сравнивался
с исходниками поправки профиля Tier 3 из `92e9dbc3`. На доске 17 завершённых узлов
L1 и шесть открытых направлений L0.

## Поправка профиля

Нативный `plan/save` принимает полные профили через `repair_gate_profiles`
с прежними `plan_id`, `title` и `goal`. После закрытия L1 этот запрос
может заменить `direction` и `environment` в открытых L0 с нулевым
digest. Сохранение увеличивает ревизию, пересчитывает хэши изменённых L0
и записывает прежний и новый хэши конфигурации gate в журнал.
Тест с перезапуском ядра проверил сохранность L1, его контракта,
прошедшей попытки и квитанции Blast. Повтор запроса идемпотентен.

Целевой прогон дал 131 passed. Ruff, basedpyright для изменённых
исходников, проверка слоёв и проверка сырого SQL прошли.

`ContainerGateRunner` запускал команды при отключённой сети, без
добавленных capabilities, с корневой ФС и checkout только для чтения.
В проверочном checkout `.venv-core` и `.venv-ui` указывали на среды
в `/opt/aconsole`. Использование `.venv-ui/bin/python` также сохраняет
ожидаемый префикс интерпретатора в smoke-тесте.

Тесты задержки ядра по умолчанию пишут JSON в `.aconsole-dev/core2-latency`.
Для readonly-прогона добавлен параметр среды `ACONSOLE_TEST_LATENCY_DIR`.
В проверочном профиле он указывает на `/tmp/aconsole-gates/latency`.

Первый полный прогон UI на слое GTK и Xvfb дал 536 passed, 17 failed,
1 skipped. После добавления XTest, включения доступности и запуска
через `.venv-ui/bin/python` 12 из 17 падений исчезли. Пять оставшихся
воспроизвелись на `0bf2f5cc` в том же окружении. Это мастер настройки,
три сравнения скриншотов DES3 и остановка таймера бейджа окна.

После установки полного Git и переноса отчётов задержки во временный
каталог прогон из 200 тестов прошёл. В него вошли поправка профиля,
Tier 3, IPC, предпроверка патча, буфер обмена и операции Git. Отдельный
прогон на итоговом образе с `curl` дал ещё 57 passed, включая ранее
падавшие четыре сценария нативных хуков и smoke ядра.

На первом образе полный набор ядра собрал 2743 теста. В сохранившейся
части прогона есть результаты 2174 тестов, из них 2136 passed, 26 failed
и 12 skipped. Для этого прогона итоговой сводки нет.

На 2026-11-20 подтверждено, что сверка Alembic видела `note_fts` и пять
служебных таблиц SQLite FTS5 как лишние. В `457aed0e` эти шесть имён
исключены из автогенерации. Проверка обнаруживает постороннюю таблицу
с тем же префиксом. `alembic check` прошёл на новой базе с применёнными
миграциями, целевой набор проверок миграций и отката дал 4 passed.
Отдельный локальный прогон миграций, FTS, PTY sidecar, submodule cleanup
и отказа Git hook дал 18 passed. Полный повтор на итоговом образе ещё нужен.

## Условия приёмки на живом проекте

Зарегистрированный checkout проекта находился на `7451c9e7`. Он содержит
локальные `.venv`, `.venv-core` и `.venv-ui`, которые проверка sealed-среды
отклоняет. В снимке живого AConsole были две активные вкладки проекта.
Ядро занимало 240,56 МиБ RSS, интерфейс — 154,73 МиБ RSS. Пороги Tier 3
составляют 120 и 150 МиБ соответственно при минимум пяти вкладках.
Предыдущий контрольный замер ядра для MEM-1 составил 173,125 МиБ.
Работа по снижению RSS отложена в `TD-HDG-MEM-1`.

Поправка проверена на отдельном экземпляре ядра. Для живого плана ещё
нужны интеграция исходников, проходной запуск через `plan/directionGate`
и приёмка шести направлений человеком.
