# 0.1.1 — добавление агента в занятую сессию

Причина: `tab/open` создавал второго исполнителя правильно, но выбор новой вкладки
сразу вызывал `tab/launchSpec`. Ядро отклоняло одновременный запуск в общем каталоге
через `WORKTREE_BUSY`, а UI показывал это как ошибку. Затем передача из Git-экрана
пыталась дождаться завершения не запущенного терминала и не продолжала запуск.

Исправление:

- Вкладка сохраняется и показывает «Агент добавлен в сессию» с объяснением ожидания.
- Кнопка передачи управления находится прямо во вкладке. Только подтверждение
  вызывает штатный `workSession/handoff`: остановка, проверка процессов и снимок.
- После успешной передачи запускается выбранный агент. Отказ или отмена не запускают
  его. При неудавшемся первом старте не ожидается завершение несуществующего процесса.
- Защита одного исполнителя в общей копии сохранена. Параллельная работа по-прежнему
  требует изолированных worktree.

Регрессионный тест ядра теперь добавляет вторую вкладку уже после выдачи первой
launch reservation. UI-тест воспроизводит отказ запуска, ожидание без ошибки,
отмену передачи, подтверждённую передачу и успешный настоящий VTE spawn `/usr/bin/true`.
Нативные CLI и рабочие агенты пользователя этим тестом не затрагиваются.

Первый совмещённый GUI-прогон упал в нативном GTK/Gio после терминальных тестов,
при старте следующего сценария Git. Отдельные прогоны указанных файлов завершились
успешно; полный GUI-набор для этой доработки повторно не запускался.
