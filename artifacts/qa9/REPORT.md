# QA-9: отмена конфликтного rebase

База: `61257760e032814ec2d371a6e4ded4e84ceb8cb9`, 2026-11-09.
Продуктовый код совпадает с исходным отказом на `964f1a25`; промежуточные
QA-8/QA-10 меняли проверки readers и golden контракта.

## Что проверено

Исходный полный GUI-прогон QA-8: **506 PASS / 1 FAIL / 1 deselect**, 206.12 s
(`../qa4-scenarios/full-ui-coverage.xml`). Тест не дождался одновременно
чистого worktree и исходного HEAD после abort. Отдельный прежний прогон:
**1 PASS**, 7.83 s. В исходном JUnit нет ответа abort или сообщений интерфейса,
поэтому по нему нельзя установить, отказал Git, RPC или выбор строки.

Повтор QA-9 на неизменных `src/` и `tests/`, native Xvfb, английская локаль,
с branch coverage: **507 PASS / 1 deselect**, 198.05 s (`baseline-full.xml`).
Затем тот же сценарий запущен **10 раз в отдельных pytest-процессах** с тем же
покрытием: **10 PASS**, 8.88–10.06 s каждый (`isolated-probe-01..10.xml`).
Во всех десяти трассах rebase вернул `conflicted`, а abort — `ok=True` и исходный
HEAD. Последующие исходные проверки чистоты worktree, HEAD и отказа устаревшего
commit также прошли.

Итоговый полный прогон с диагностикой: **507 PASS / 1 deselect**, 192.84 s
(`final-full.xml`). В трассе abort также вернул `ok=True` и исходный HEAD.
Оба полных набора прошли целиком с прежним исключением PERF-7. **QA-9 завершён
по критерию документированной невоспроизводимости.**

## Изменение проверки

В `tests/gui/front/test_git_actions.py` при прежнем отказе ожидания добавляются
exception notes: сообщения интерфейса, выбранная строка, ожидаемый/фактический
HEAD и porcelain status. Исходный assertion повторно выбрасывается. Условие
чистоты и HEAD, время ожидания, опрос и проверка устаревшего commit сохранены.
Дополнительный диагностический status после отказа использует
`--no-optional-locks`.

Опциональный pytest plugin `qa9_probe.py` записывает реальные параметры и
ответы `git/rebase` и `git/abort`, затем возвращает исходный результат или
повторно выбрасывает исходное исключение. Повторов запроса и подмены ответа нет.
Трассы сохранены в `*-trace.txt`, JUnit и сводка — в `results.json`.

## Вывод и ограничения

Исходный отказ пока **не воспроизведён; причина не установлена**. Это результат
расследования невоспроизводимости, а не исправление доказанного дефекта.

- `GitViewModel.abort()` передаёт только `project_id` и `worktree`; revision
  не входит в `WorktreeOperationParams`. Данных для диагноза «гонка revision» нет.
- Опрос теста через обычный `git status` допускает необязательную блокировку
  индекса; чтения приложения в `GitRunner` выставляют `GIT_OPTIONAL_LOCKS=0`.
  Это возможное вмешательство наблюдателя, но ни один сохранённый ответ не
  подтверждает отказ из-за `index.lock`. Менять опрос ради зелёного результата
  по этой гипотезе не стали.
- Запись RPC может влиять на расписание. Поэтому полный прогон без plugin
  сохранён отдельно. Конечная серия повторов не исключает редкий отказ.
- Один прежний PERF-7 deselect сохранён в обоих полных прогонах.
- В каждом полном прогоне 413 warnings, включая прежние предупреждения о
  coroutine `MainWindow._renew_git_watch` и deprecated GTK API. Это не прогон
  без предупреждений; причины этих предупреждений данным узлом не менялись.
- Общий порог покрытия, core/performance, CI, deb-install и независимый gate
  этим узлом не принимаются. QA-4 остаётся failed; последний общий результат
  QA-8 — 89.302931% при пороге 90%. DES-3 требует пользовательской приёмки.

Ruff для изменённого теста и plugin, `git diff --check`: PASS.

## Воспроизведение

На хосте из корня дерева, с Python GTK-окружения проекта:

```sh
/path/to/.venv-ui/bin/python artifacts/qa9/gtk-runner.txt --full-ui --coverage --label baseline-full
/path/to/.venv-ui/bin/python artifacts/qa9/gtk-runner.txt --git-actions --coverage --diagnostics --repeat 10 --label isolated-probe
/path/to/.venv-ui/bin/python artifacts/qa9/gtk-runner.txt --full-ui --coverage --diagnostics --label final-full
python3 artifacts/qa9/summarize.txt
```

Для повторения первого baseline нужен checkout базы `61257760`; итоговый
checkout содержит только диагностическое дополнение теста. `baseline-source.json`
и `final-source.json` фиксируют базу и хеши итоговых исполняемых файлов.
Runner извлекает Xvfb во временный каталог без установки системного пакета.
Сырые coverage и журналы локальные; JUnit/трассы/сводка сохранены в Git.
Серия первых baseline/isolated использовала один временный coverage-файл:
он не является новым общим отчётом покрытия QA-4. Итоговый runner сохраняет
coverage отдельно для каждой метки прогона.
