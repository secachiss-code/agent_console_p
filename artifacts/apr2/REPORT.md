# APR-2: полные сведения перед согласованием

База: `d4f0eae4673f2f8cc6806dbb2434c205316331cc`.

## Результат

Рабочий HTTP handler теперь формирует `EditDetail` для Write/Edit/MultiEdit и
`GenericDetail` для MCP и неизвестных инструментов. Пути и предлагаемые фрагменты
правки видны в карточке, предпросмотр свёрнут и ограничен 200 строками. Все входные
аргументы, включая content, replace_all и последовательность edits, доступны отдельно.
Неподдерживаемая форма входа остаётся полностью читаемой как JSON.

У длинных команд и аргументов есть «Прочитать целиком». Только краткое представление
ограничено 4000 символами. Раскрытие сохраняет весь текст, включая конец команды;
управляющие символы и bidi-коды остаются видимыми кодовыми точками. Полное содержимое
создаётся лениво, детали прокручиваются отдельно от кнопок решения. Поле input_json
у EditDetail необязательное; прежние сообщения по-прежнему декодируются. Шесть
зависимых IPC-схем перегенерированы.

Литеральные пути проверяются без shell-разбора. Git, конфиги агентов, инструкции
AGENTS.md/CLAUDE.md/GEMINI.md и подобные защищённые пути помечаются как destructive;
карточка правки называет это «Меняет защищённые файлы». Отдельно отмечаются секреты
и выход за worktree. Отсутствующий cwd заменяется известным worktree вкладки.
MCP с аргументом command не превращается в shell-команду и не получает правила
«разрешать до закрытия вкладки».

IngestApp следит за http.disconnect, отменяет обработчик и дожидается его очистки.
ApprovalHold учитывает ожидающих клиентов: уход последнего отменяет запрос,
публикует ApprovalResolved(cancelled), убирает карточку из snapshot и освобождает
таймер. Уход только одного из дубликатов не лишает оставшегося клиента ответа.
После отмены поздний Allow отвергается; решения и timeout сохраняют прежнее поведение.

  PermissionRequest → сериализованный ApprovalView → решение пользователя,
  настоящий TCP-разрыв Uvicorn → отмена карточки, дубликаты, прежние approval/native,
  ingest HTTP и lifecycle-проверки. Отдельно проверена правка только завершающего LF.

  Новые сценарии раскрывают команды, diff и generic JSON, проверяют последний файл,
  конец текста после 4000 символов, экранирование управляющих символов и доступность
  трёх кнопок при ширине 700 px. Три viewmodel-теста входят в оба прогона.
- Полный Ruff и полный strict basedpyright: PASS, 0 ошибок/предупреждений.
- `check_contracts.py`: **11 checks PASS**. Две проверки docs/contracts пропущены
  штатно, поскольку docs не подключены к worktree. Проверены регенерация схем,
  совместимость и опубликованные маршруты настоящего изолированного ядра.
- `git diff --check`: PASS.

Первый sandbox-прогон прерван после отказа и зависания; он не засчитан.
Успешные socket-проверки повторены вне sandbox. Первый запуск check_contracts
остановился без локальных ссылок на .venv-core/.venv-ui; после подключения существующих
окружений прошёл. В промежуточной новой GTK-проверке была ошибочная английская
строка при русском desktop: 1 FAIL/34 PASS. Проверка исправлена для обоих поддержанных
языков; отдельный XML промежуточного отказа не сохранён, финальный повтор — выше.
XML санированы от личного домашнего префикса и hostname без изменения счётчиков,
таймингов, результатов и сообщений проверок.

## Снимки, Surprises & Discoveries

Применён gtk-screenshot-review. Использован established fallback APR-1:
отдельный Xvfb и FakeCore текущего worktree, временные XDG-каталоги и Xauthority.
hostrun ui-snapshot не предоставляет подходящего запуска текущего worktree;
проверка его аргументов отказала. Пакет Xvfb скачивается и извлекается во временную
папку без установки. Пользовательские настройки не меняются.

Для Edit, MCP и длинной команды сняты light/dark 1280×800 и light 700×800.
Девять изображений в ui/ открыты и сверены с DESIGN §1 и §2.1: карточка поверх
терминала, отдельная прокрутка деталей, кнопки видны, ключи перевода не показываются,
в узком окне нет обрезания карточки, в dark нет светлых областей карточки.

- При правке конфига исходная метка destructive говорила «Удаляет данные»;
  исправлена на «Меняет защищённые файлы», снимки повторены.
- «Сессия завершена» позади карточки относится к терминалу FakeCore, не к
  согласованию. Эти снимки не доказывают работу настоящих CLI hooks.
- Preview остаётся моноширинным текстом в существующем GTK-представлении;
  GtkSourceView и подсветка синтаксиса из DESIGN не добавлены: такой зависимости
  в поставляемом runtime сейчас нет. Все строки и полный вход доступны.

## Границы подтверждения

Diff строится по данным hook, без чтения одноимённых файлов хоста. Для Edit это
переданные old/new-фрагменты; для Write — новое содержимое, а не сравнение с
предыдущим файлом на диске. Существование файла, соответствие old_string файлу и
фактическое применение операции проверяет агент. Полные исходные аргументы не теряются.

Path risk — лексический: core не разрешает симлинки в отдельном mount namespace
агента. Отмена проверена на уровне настоящего HTTP transport и брокера; реальные
CLI, их режимы и отдельные протоколы перехвата остаются в APR-5…APR-8/AUD-2/QA-6.
Полная сборка пакета, CI и ранее падающий frame-time здесь не проверялись.

## Воспроизведение

Из корня текущего worktree с существующим core environment:

```sh
PYTHONPATH=src <core-python> -m pytest -o addopts= -q \
  tests/core/test_permission_details.py tests/core/test_approval_hold.py \
  tests/core/test_approval_native.py tests/core/test_ingest_http.py \
  tests/core/domain/test_approvals.py tests/ui/test_approvals_vm.py
```

Для GTK на хосте передать абсолютные пути UI Python и runner:

```sh
distrobox-host-exec <ui-python> <worktree>/artifacts/apr2/runner.txt
```

runner поддерживает --tests-only и --captures-only. Код сценария — capture.txt;
хеши источников и снимков — source.json.
