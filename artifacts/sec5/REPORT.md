# SEC-5: согласования изолированы по вкладке и контексту вызова

2026-11-06, база main 72bb409. MCP node-12, SEC-5.

Ключ pending-дедупликации теперь (tab_id, session_id, tool, input_sha256).
Ключ повторной доставки дополнительно содержит event_id. Один event_id
в другой вкладке/сессии, для другого инструмента или с другим входом не
переносит завершённое ALLOW/DENY. Стабильный event_id того же вызова и
pending-дедупликация в одном контексте сохраняют поведение SEC-2.

Центральный обработчик TabRemoved в bootstrap вызывает ApprovalHold.drop_tab:
отменяются pending waiters, убираются views/timers/settled/replay записи и
запомненные правила только закрываемой вкладки. Другая вкладка продолжает
ожидать своё решение. Закрытый hook получает native fallback, не ALLOW.

Bootstrap — дополнительный файл core для daemon wiring критерия очистки.
Расширение области записано в note узла до правки; механизм drop_tab уже
существовал в broker, но из реального пути закрытия не вызывался.

## Воспроизведение и проверки

Первый RED дал семь доменных отказов изоляции. Начальная HTTP-фикстура
упёрлась в WORKTREE_BUSY при двух launchSpec в общей эстафете. Исправлена
только новая фикстура: независимые проекты/workspace. После этого публичный
tab/close воспроизвёл именно зависание held hook (close-red.txt), до правки кода.

После исправления все 13 новых случаев PASS. Финальный профильный набор:
162 PASS; включает прежние lifecycle/TTL, nonce, one-time ALLOW, replay,
память, native fallback и HTTP auth тесты. Существующие тесты не менялись.
Публичный временный daemon: вкладки/launchSpec/close/decision/snapshot через
Unix IPC, permission hooks по настоящему HTTP. После закрытия первой вкладки
её запрос освобождён, второй остаётся pending и отдельно получает DENY.
Контейнерные порты в этом тесте fake; настоящие CLI и пользовательские вкладки
не запускались и не закрывались.

Полный hostrun test core: 1779 PASS, exit 0.
hostrun check-final: exit 0; Ruff/strict types/architecture/contracts PASS.
Known ownership-подшаг Not a git repository не подтверждён. Старый phase gate
не принимает SEC-5 ID; его успешный результат не заявляется.
