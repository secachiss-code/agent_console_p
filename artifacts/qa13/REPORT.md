# QA-13: границы проектов и восстановление знаний MCP

База: `e1c3807acc07189dfaf793f86d4522f4a040a8e7`. Продукт и настройки покрытия
не менялись. Все новые операции вызываются через настоящий `mcp.Client(server)`.

20 сценариев проверяют:

- отказ публикации фактов с неправильным, абсолютным, выходящим за worktree или
  отсутствующим источником; допустимый локальный источник вне Git checkout;
- отказ чужих идентификаторов при supersede, handover, impact, выборе плана и
  контекста узла без изменения локальных знаний;
- фильтр контекста по путям узла, поиск, порядок актуальных и устаревших фактов,
  ограничение выдачи с признаком усечения;
- циклы и дубликаты графа влияния, точные границы усечения, фильтр типов,
  сохранение знаний при отказе codegraph extractor;
- неявный выбор плана: удерживаемый lease имеет приоритет, затем выбирается
  последний план своего проекта;
- отказ SQLite при supersede и замене handover: прежние данные остаются как
  в памяти, так и после открытия нового engine, затем повтор записи успешен;
- разделение двух проектов после перезапуска; handover удалённой вкладки
  сохраняется в базе без владельца и не присваивается другой вкладке.

В последних четырёх сценариях настоящие SQLite, миграции, Writer и репозитории.
Ошибка записи инъецируется на границе репозитория; физическое заполнение диска
не моделировалось. Codegraph failure использует записанный отказ порта.

проверки **31 PASS / 8.79 s** (`focused.xml`), Ruff и `git diff --check` PASS.

существующих тестов; это не объявлено исправленным.
