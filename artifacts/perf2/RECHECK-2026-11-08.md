# PERF-2: повтор на текущем main после PERF-3

База: `f5be4a2bf393c0813761ec55ae4b777a92c6323f`. Исторические REPORT.md и
hostrun-audit.json сохранены без переписывания. Новый прогон не исправляет задним
числом старый отказ max=6.125119 ms на пороге 5 ms.

## Метод

Запущен исходный test_persistence_b_tick без изменения source, assertions,
порога, workload, длительности или warmup. Плагин recheck_measure.py оборачивает
только `_tick_lags`: перед исходным вызовом и после его завершения снимает контекст;
после завершения измерения записывает статистику уже полученного списка lags.
В измерительный цикл код не вставляется. Тот же список возвращается исходному тесту,
который самостоятельно проверяет max < 0.005 и число записей.

Прогоны последовательные на хосте через distrobox-host-exec, Python 3.15.1
free-threading, PYTHON_GIL=0; фактическое gil_enabled=false записано в JSONL.
PYTHONPATH явно указывает src текущего worktree, а не editable install другого checkout.
Оба исходных файла сравниваются byte-for-byte с HEAD до запуска; SHA-256 в run.json.
Намеренной параллельной нагрузки агент не запускал, ambient load не контролировался.

## Вывод и ограничения

Исторический выброс пока не воспроизведён. Причина единичного max=6.125119 ms
остаётся неизвестной; данные не позволяют приписать его GC, scheduler, writer,
локализации или конкретному предыдущему исправлению. Продуктовый writer и
существующий benchmark не менялись. Изменение алгоритма без подтверждённой
причины на основании этого прогона не предлагается.

PERF-3 уже устранил независимый отказ startup recovery в fault-injection тесте;
его исправление не заявляется исправлением writer tick. Успех текущего набора
не является гарантией отсутствия будущих выбросов под иной нагрузкой.

## Артефакты и воспроизведение

- recheck-isolated-run.json и recheck-full-run.json: фиксированный commit,
  исходные хеши, Python, argv, cwd, exit codes и wall time.
- recheck-isolated{1,2,3}.jsonl и recheck-full.jsonl: числовые результаты и нагрузка.
- Одноимённые XML и logs: полный исходный verdict pytest.
- recheck_runner.txt и recheck_measure.py: воспроизводимый запуск и наблюдение.
