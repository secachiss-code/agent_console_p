## Исправление отображения

Причина 30 вершин подтверждена: plan_layout.shown_nodes обрезал вход до30,
сначала выбирая verifying/in_progress. Из-за этого пользователь видел только
часть графа, а принятые зелёные узлы вытеснялись. CSS также окрашивает
in_progress и verifying одинаковым жёлтым. Счётчик считал done всего плана,
что не соответствовало количеству показанных карточек.

Обрезка удалена: shown_nodes возвращает каждый входной узел в исходном порядке.
Раскладка и зависимости сохранены. Большой граф доступен через прокрутку;
размер экрана больше не определяет, какие вершины вообще существуют в графе.

## Правило завершения — прямое решение пользователя kb-127

потом конкретная эскалация при невозможности исправить. Идущая работа — жёлтая.

## Полный UI-прогон: подтверждённый красный результат

Полный hostrun test ui: два отказа test_spike.py; остальные151 проверка PASS.
Отдельный повтор spike воспроизводит тот же отказ. В stderr указана причина:
libpango-1.0.so.0 не найден в devtools, GObject TYPE_NONE при импорте GTK.
Тесты и пороги не менялись ради зелёного результата. Полный UI не объявлен PASS.
Тест проекции реального snapshot (все71 узел и концы79 blocks) отдельно PASS.

По правилу пользователя PLAN-2 остаётся красным, пока проверка GTK/активация
исправленной версии UI не завершена. Исходный код полного графа и артефакты
зафиксированы; зелёная отметка за весь UI не выставляется по малому demo.
