# CORE-8 — конкурентный echo-журнал vault

Обнаружено при wire-проверке UX-3 с экспортом 200 заметок:
watchdog observer завершился с `RuntimeError: dictionary changed size during
iteration` в `EchoBook._prune`. Название EchoWindow в начальной формулировке
узла неточно; фактический класс — EchoBook.

Vault writer вызывает remember из рабочего потока, а observer параллельно
вызывает is_echo. Оба метода меняли общий `_seen` через prune без синхронизации.
Один Lock теперь защищает remember, is_echo и чтение размера журнала. Формат
заметок, срок TTL и смысл сравнения хешей не меняются.

Новая регрессия удерживает prune в потоке reader, запускает remember в другом
потоке и подтверждает, что запись ожидает освобождения критической секции.
После освобождения просроченная запись исчезает, новая распознаётся как echo.
В версии без блокировки writer завершался бы до освобождения reader.

Проверка текущей рабочей копии в devtools: `test_vault_writer.py`,
`test_vault_wire.py` и находящийся в работе `test_palette_wire.py`:
**12 passed**, без прежнего PytestUnhandledThreadExceptionWarning.
Самостоятельные vault-тесты составляют 10 случаев этого набора.
Ruff изменённых файлов проходит; изменения фиксируются отдельно от UX-3.

Установленное ядро и пользовательский vault не менялись; использованы
только временные каталоги тестов. Поведение file watcher за пределами
подтверждённой гонки остаётся в соответствующих узлах плана.
