# QA-36 — подтверждённый OS exit полного набора QA-6

Полный прежний набор QA-6 на `547001714bdc49e58898671425fca3b7bc4576e5`
завершился с **pytest exit 0 и collector exit 0**: 2217 passed, 1 skipped,
без ошибок и таймаута. Исходники до/после совпадают, Python 3.15.1 free-threaded,
GIL выключен как у сборщика, так и при pytest sessionfinish.
Продолжительность наблюдения — 453.224 секунды.

## Что установлено

Новый прогон снимает неопределённость OS exit **этого прогона**. Причина двух
исторических SIGTERM/143 не установлена и не объявлена исправленной.
Старый `run_core.py` уже запускал pytest с `start_new_session=True`, сроком 900 с
и отдельным сохранением начальных данных. Из этих записей нельзя восстановить
отправителя сигнала или фактический exit старого pytest. Исторические записи
сохранены, их hashes перечислены в `historical-inputs.json`.

Новый диагностический сборщик создаёт свежий output, сохраняет состояние атомарно,
регистрирует полученные TERM/INT/HUP с повторной доставкой исходного сигнала и
наблюдает за дочерним процессом в отдельной группе. Он не подменяет OS exit JUnit.
Лимит 900 с не достигнут, сигналы сборщику не зарегистрированы.
В pytest загружен только дополнительный наблюдатель завершения: спустя 45 с после
sessionfinish он выдал бы повторные стеки оставшихся потоков. Процесс завершился
раньше, поэтому дампы не потребовались. Проверки и таймауты тестов не менялись.

`run-1/result.json` сохраняет команду, HEAD, PID/PGID, timestamps, manifests до/после,
настоящий returncode дочернего процесса и SHA256 лога. `run-1/pytest.xml` и
`run-1/pytest.log` — новый результат. Точные запущенные bytes сборщика и probe
сохранены как `executed-*.py.txt`. Публикуемые `.py` после запуска получили только
аннотации типов, именованную константу прежнего лимита 900 с и lint-комментарии;
повтор полного набора после этих косметических правок не выполнялся.

Набор: tests/core, contracts, gate, hostrun, smoke и пять прежних package/packaging/
contrast/build_guards/socket_paths файлов, `-m "not performance"`. Это тот же scope,
что у старого collector, с наблюдателем `artifacts.qa36.shutdown_probe`.
Проверка выполнялась внутри агентской среды в worktree `038657e1539f15ad`;
интерпретатор взят из `.venv-core` основной копии, cwd и тесты — указанной ветки.
Предупреждения Python о forkpty в многопоточном процессе сохранены в логе.
