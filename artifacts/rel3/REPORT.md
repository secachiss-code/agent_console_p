# REL-3 — dangling symlink при восстановлении чекпоинта

База: `5f74c3c`. Узел: `plan-1/node-86`.

Причина из AUD-3 (`Path.is_file()` пропускает битые симлинки) уже устранена
коммитом `f410c5e` (REL-1). Текущий `materialize` вызывает
`remove_worktree_file`: unlink относительно открытого родительского каталога,
без перехода по симлинкам. Повторное изменение реализации не требуется.

Добавлена параметризованная регрессия в `tests/core/test_checkpoints_git.py`:
битая относительная ссылка и битая ссылка за пределы репозитория удаляются при
restore, затем восстанавливаются из страховочного чекпоинта с прежней целью.
Также проверяются ignored-ссылка, внешний файл, HEAD и байты обычного индекса.
Существующие шесть `test_restore_boundaries.py` проверяют подмену родительского
каталога и сохранность внешних файлов.

Проверки:

- `git diff --check` — успешно.
- `hostrun test core tests/core/test_checkpoints_git.py tests/core/test_restore_boundaries.py`
  — 8 passed, но **в основном checkout**. Новые тесты эта команда не проверяет.
- После зависания прямой запуск тех же файлов из текущего worktree в devtools
  завершён: **10 passed**, exit 0. Использованы PYTHONPATH текущего worktree
  и абсолютные пути обоих тестовых файлов.
- Ruff изменённого тестового файла — успешно.

Приёмка подтверждает существующее исправление REL-1; изменения реализации
не потребовались. Новые регрессии фиксируют критерии REL-3 отдельно.
