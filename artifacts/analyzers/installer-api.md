# Analyzer catalog and VSIX installer integration report

`aconsole.core.infrastructure.analyzers.catalog.CATALOG` is an immutable mapping from `ruff` and `pylint` to `Analyzer` records. Each record identifies its main `Artifact` and the complete pinned extension dependency tuple. Each artifact contains its registry namespace, name, version, platform, SHA-256, and declared extension dependencies. The only currently pinned host platform is Linux x64; Pylint itself is universal. Changing a pin requires a catalog code change and review; no registry `latest` endpoint is used by the installer.

`VsixInstaller(root: Path, *, target_platform: str | None = None)` uses a private application-owned root directory. `install(key: str, *, validate: Callable[[InstalledAnalyzer], None] | None = None) -> InstalledAnalyzer` installs or updates the entire catalog-pinned closure. The optional callback receives the staged release at its final paths before activation; if it raises, the new release is cleaned up and the previous activation remains. On success the release is atomically activated. `current(key: str) -> InstalledAnalyzer | None` returns the active release. `remove(key: str) -> bool` atomically deactivates the release and returns whether it existed. InstalledAnalyzer exposes `key`, `version`, `platform`, `sha256`, `path` (the extracted extension directory), and `dependencies` (the extracted dependency directories). Removal and updates leave old release directories in place so concurrent readers can finish; lifecycle garbage collection is a separate responsibility. Unknown keys raise ValueError; registry, archive, platform and verification failures raise InstallError. Call these synchronous network and filesystem methods off the UI thread.

The installer checks the exact pinned SHA-256 for every VSIX, registry metadata identity and platform, archive entry safety and limits, package manifest identity, and the exact declared extension dependency closure. It stages all extensions before replacing the activation record. Registry TLS and code-reviewed digest pins are the trust boundary; registry signatures and execution isolation are outside this module. The data root must be private to the application user. Concurrent installs/removes use atomic pointer operations but do not serialize with one another; the last pointer operation wins.

Verified on 2026-11-22 by downloading the pinned VSIX files from Open VSX: `charliermarsh.ruff` 2026.98.0 linux-x64, `ms-python.pylint` 2026.8.0 universal, and `ms-python.python` 2026.10.0 linux-x64. All hashes matched their pins and all manifests passed dependency checks. The pin selection records observed artifacts; independent publisher signature or separate release-approval evidence was not supplied.
