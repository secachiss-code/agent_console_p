# QA-7 — готовность VTE перед проверкой bracketed paste

База: `f360ac234e751fb83cbfecc6fc67d6a7ae5ecefa`.
Изменения ограничены подготовкой тестового PTY в
`tests/gui/front/test_clipboard_routing.py` и материалами диагностики.

## Причина

Дочерний процесс писал DECSET `ESC[?2004h` в PTY, затем создавал файл ready.
Тест проверял файл и фокус виджета. Это подтверждает выполнение write() в
дочернем процессе, но не обработку вывода асинхронным парсером VTE. Первая
вставка могла произойти при ещё выключенном bracketed paste. Исходные байты
команды правильные: `1b5b3f3230303468` (input-sequence.json).

Для наблюдения diagnostic plugin добавил после DECSET команду OSC title,
журналировал title при XTest keypress, VTE commit и window-title-changed.
Подпись служит маркером обработки предшествующих байтов в том же потоке.
Существующие assertions и sleeps диагностического теста сохранены. Plugin
заменяет только метод тестового приложения в памяти, используя сохранённую
копию исходника baseline-clipboard.txt; исходный SHA256 записан в baseline.json.

`prefix-probe.xml`: **147 passed / 2 failed**,52.72с,291 deselected. Все
модули front/ui собирались, исполнялся префикс до clipboard включительно,
что сохраняет предшествующее состояние GTK и порядок тестов.

В prefix-probe.jsonl и prefix-summary.json:

- text: title пуст при keypress и первом commit, первый commit без
  ESC[200~/201~. Уведомление о разобранном OSC пришло на 79.122 мс позже commit.
- image: тот же результат; уведомление позже commit на 18.547 мс.
- mixed: marker уже установлен перед keypress; все три вставки текста и
  отдельная вставка изображения обрамлены правильно.

`isolated-probe.xml`: **6 passed**,8.30с. Во всех сценариях marker был
обработан до первой вставки; данные обрамлены как ожидалось.

Это подтверждает гонку готовности фикстуры. Почему именно в данном полном
процессе VTE отставал по обработке вывода, отдельно не профилировалось;
доказательство не требует предположения о конкретном источнике задержки.
Величины выше — интервалы до callback уведомления, а не точное измерение
начала/конца внутреннего парсинга VTE.

## Исправление

Дочерний процесс теперь одним write() отправляет DECSET и следующий за ним
OSC2 с известным title. Проверка готовности ждёт этот title вместе с файлом
ready и прежним фокусом. После ограниченного ожидания title явно проверяется
до отправки первого XTest события клавиатуры.

Сохранены 100 итераций по 20 мс и все прежние sleep. По сравнению AST
(assertions.json) все 14 исходных assertions сохранены, добавлен 15-й.
Проверяются прежние точные байты, Unicode и переводы строк, три сочетания
клавиш, приоритет текста над изображением, принудительная вставка изображения,
отмена при смене фокуса и отсутствие перехвата вставки в обычное поле.
Добавлен явный require_version Gdk 4.0 для независимого запуска теста.

Сценарии идут через нативный GTK/VTE PTY и XTest события по реальному пути
обработки клавиатуры окна; вызов обработчиков напрямую их не заменяет.

В диагностическом префиксе отказали text/image, а прежний общий набор
показывал text/mixed. Инструментирование влияет на тайминг; вывод основан на
состоянии при конкретном commit, а не на неизменном списке падающих MIME.
Строки traceback динамического метода сдвинуты относительно исходного файла;
для порядка событий используются JSONL и сохранённый baseline исходника.

## Проверки кандидата

Изолированный исходный набор без диагностической подмены:
**6 passed**,8.77с; isolated.xml/isolated.log. Исходные точные assertions
обрамления и текста, image-only, empty/cancel/copy проходят.

Runner создаёт приватный Xvfb с временными Xauthority/config/state/cache и
направляет XTest только в его окно. Пакет Xvfb распакован без установки.
`--mode full` запускает весь tests/gui/front и tests/ui без исключений;
`--mode prefix` собирает тот же набор и исполняет только префикс до clipboard;
`--mode isolated` запускает шесть clipboard-сценариев. `--probe` отдельно
включает подмену методом из сохранённого baseline для воспроизведения старой
гонки. Все GUI-прогоны в этой работе выполнялись последовательно.

Полный набор без диагностической подмены: **438 passed / 2 failed**,167.86с,
440 тестов, 412 warnings — full.xml/full.log. Все шесть
`test_real_clipboard_shortcuts[...]` прошли, в том числе text и mixed;
проверяемая выписка — full-clipboard-summary.json.

Оставшиеся отказы:

- Известный PERF-5: Git history median 83.2 мс при пороге 17.5 мс в software Xvfb,
 47 frames/4 с, RSS 2140 MB.
- Новый единичный выброс `test_rank_2000_under_16ms`:144.533 мс при пороге 16 мс.
  Он сохранён отдельным узлом PERF-6. По этому наблюдению не устанавливается
  причина и не утверждается связь с изменением clipboard readiness.

Общий GUI PASS не заявляется. Assertions обоих performance-тестов и их
реализации в QA-7 не менялись. Ruff теста и git diff --check проходят.

В XML/log убраны пробелы в концах строк traceback; атрибуты suites и
результаты тестов сохранены. JSONL и baseline исходника сохранены дословно.
