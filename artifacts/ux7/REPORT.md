# UX-7 — приёмка и возврат узла плана

База: `eb1fd523`; plan-1/node-70.

## Уточнение прежнего критерия

Кнопки и evidence уже были реализованы в 997074f1/017e4fab, но узел оставался
открытым. Старый критерий «агент не может verifying → done» позднее уточнён
решением пользователя kb-127 / PLAN-3: daemon использует checked completion,
а владелец с новым evidence может завершать работу. Основание в репозитории —
[отчёт PLAN-3](../plan3/REPORT.md), коммит b4183fcc. Эта политика сохранена.
В явно ручной политике MCP-агент по-прежнему не принимает узел; новая ручная
операция возврата также недоступна агенту. Тесты проверяют обе политики.

## Что исправлено

Раньше «Вернуть» выполняло два RPC: verifying → failed → pending. Отказ второго
запроса оставлял промежуточный failed, хотя пользователь просил вернуть в очередь.
Теперь это один человеческий переход verifying → pending, один commit БД и одно
событие. Ошибка записи откатывает узел и ничего не публикует. Возврат сохраняет
исходное evidence; причина возврата хранится как note.

PlanGraph отслеживает незавершённые решения по ID узла. Двойное нажатие не
дублирует запрос, другой узел можно проверить параллельно. Ответ по одному узлу
не включает кнопки ещё ожидающего другого. MainWindow захватывает исходную
страницу до старта coroutine: поздний ответ не меняет busy новой страницы.
UI не присваивает новый статус оптимистически, подтверждённое событие ядра
обновляет граф; отказ показан существующим toast.

Отчёт и кнопки расположены под заголовком, выше нижнего overlay согласований.
Длинный отчёт прокручивается в своей области, его можно выделить/скопировать;
длинные слова переносятся. Скрывать/переставлять саму панель согласований не
потребовалось — APR-1 остаётся отдельной задачей.

Изменение domain/plan.py необходимо для атомарного возврата; расширение paths
отмечено в note. Поля RPC, схема БД и JSON-схемы не менялись.

## Surprises & Discoveries / визуальная проверка

Применён gtk-screenshot-review; просмотрены9 PNG: plan-review, plan-pending,
plan-done, каждый light1280×800, dark1280×800 и light700×800.

- Отчёт и кнопки нужны выше нижней панели согласований: приёмка видна даже
  при открытом demo approval. Ни панель, ни её модель в UX-7 не менялись.
- При700px отчёт переносится и прокручивается в96px области; кнопки «Принять»
  и «Вернуть» целиком доступны. В pending/done они скрыты. Широкий граф
  прокручивается горизонтально, как до изменения.
- Тёмные виды не имеют светлых участков; подписи переведены, имена Node2… —
  содержимое demo-фикстуры. В макетное соответствие не включён отсутствующий
  docs/design/DESIGN.md.
- hostrun относится к основному checkout; использован нативный UI venv и
  приватный Xvfb с временными config/state/cache/Xauthority. Пакет извлечён
  без установки, рабочий дисплей пользователя не использован.
- Первые новые тесты ошибочно сравнивали возрастной priority, читали evidence
  из NodeBrief и вызывали несуществующий cleanup. Тесты исправлены: проверяются
  все постоянные поля и восстановленный domain node, cleanup использует
  существующий lifecycle. Это не объявляется дефектами продукта.

Снимки используют FakeCore. Пользовательский план, его узлы и рабочая БД не
принимались и не изменялись напрямую; тесты работают только с временными данными.
Настоящие оплачиваемые CLI-беседы не запускались.
