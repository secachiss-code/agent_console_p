# QA-12: восстановленные вкладки до перехода на work sessions

База: `1c503c82bd2032d7858f3523669da3a9e8cbd7bc`, 2026-11-09.
`src` и настройки coverage не менялись.

## Проверяемые сценарии

27 сценариев восстанавливают вкладки без `work_session_id` из настоящей SQLite
через публичный `TabService.reload()`. После операции writer останавливается,
engine уничтожается; новое соединение проверяет открытые вкладки и сохранённую
отметку удаления workspace. Соседняя вкладка и её workspace должны сохраниться.

- Dirty, ahead и ignored запрашивают решение до остановки процессов; признак
  dirty переживает повторное открытие базы. Remove не удаляет tracked changes.
- Keep закрывает вкладку и освобождает worktree, сохраняя запись workspace.
- Clean удаляется без дополнительного решения; ignored удаляется только при
  явном remove с `discard_ignored=True`.
- При отказе Git remove workspace остаётся; результат отражает свежее состояние
  clean/dirty/ignored. Если повторная проверка недоступна, возвращается kept.
- Ошибка orphan scan, ошибка kill и выживший процесс сохраняют worktree даже
  после решения remove. Main checkout и existing worktree не удаляются.
- Restart останавливает старый PID и найденный orphan до нового состояния;
  матрица resume × fork_pending проверяет сохранность диалога и pending fork.
  Пока fork не завершён, view скрывает родительский session id.
- Неудачный restart допускает повтор без потери диалога; отсутствие session id
  и агент без resume capability отказывают до каких-либо действий с процессами.

SQLite, миграции и Writer реальные. Git/Podman/process ports — записывающие
стенды: эти проверки проверяют решения сервиса и долговечность данных, а не
физическое удаление каталогов или остановку настоящих процессов.

## Воспроизведение

Из корня checkout с существующим core Python окружением:

```sh
/path/to/.venv-core/bin/python artifacts/qa12/run.txt --new-only
/path/to/.venv-core/bin/python artifacts/qa12/run.txt
/path/to/.venv-core/bin/python artifacts/qa12/summarize.txt
```

`--new-only` запускает новые 27 сценариев; обычный запуск добавляет существующие
`test_tabs.py` и `test_tabs_restore.py`. Для IPC нужен хостовый запуск через
`distrobox-host-exec`. Порог отключён только при сборе данных; summarize отдельно
вызывает настоящий `coverage report` с неизменным порогом 90% и сохраняет exit code.

Первый пробный запуск остановлен на ошибке обращения теста к несуществующему
полю AppSnapshot.focused_tab. Второй дал 21 PASS до ошибочного ожидания видимого
session id при pending fork. Исправлены тесты; продукт и его assertions не менялись.
Ограниченный related-запуск дошёл до 61 успешной проверки, затем остановился без
итогового результата; прерван. Этот запуск не считается PASS.
