# DES-4 — единая локализация и язык сообщений ядра

База: `249eb00f`; plan-1/node-55. Изменения ограничены локализацией,
передачей данных для неё и необходимыми проверками. Дополнительные пути ядра,
форматтеров, каталога и компилятора указаны в note узла до реализации.

## Реализация

- `ui/i18n.py` — один механизм на GNU gettext. Каталоги en/ru — обычные UTF-8
  PO и воспроизводимые MO; стандартный compiler в tools/compile_translations.py
  не требует системного msgfmt. Семь прежних modules/messages.py остались
  совместимыми экспортами API, без словарей и выбора языка. Сюда же перенесены
  тексты ошибок ядра и горячих клавиш. Desktop locale выбирает русский или
  английский; прочие локали используют английский. Процессный setlocale не
  вызывается, локаль не меняется при каждом формате.
- Русский plural rule учитывает 11–14 и окончания 1/2–4/5–0: день/дня/дней,
  файл/файла/файлов, запрос/запроса/запросов, коммит/коммита/коммитов.
  Счётчики, требующие склонения, выбирают ngettext до подстановки числа.
  Формы проверяются на 0,1,2,5,11,14,21,22,25,101,111.
- Числа, стоимость сессий/моделей и длительности диагностики используют
  общий format_number: точка/запятая и группировка через comma/NBSP.
  Календарные даты в списках и квотах используют format_date: русский
  день-месяц и английский ISO порядок, с прежней локальной временной зоной.
- Ядро передаёт стабильные UiMessage ID вместо UI-предложений: отказ доставки
  в незапущенную вкладку, очередь комментариев, ошибки и команды палитры,
  область восстановления снимка, запрос согласования и предупреждение hooks.
  UI переводит их на границе отображения. Тексты внешних ошибок и прежнего
  ядра, не являющиеся известными ID, сохраняются как данные.
- CheckResult.detail может содержать tagged JSON setup_detail.v1: коды
  наблюдений и отдельные значения контейнера/пути/монтирования. Коды и данные
  описаны в contracts/messages.py и contracts/setup_detail.py. Значения не
  разбираются по разделителям и не служат форматными шаблонами. Пояснения
  изоляции теперь переводятся в мастере и health; успешная проверка не
  получает текст предупреждения. Поля существующих RPC/схем не менялись.
- Подписи палитры переводятся перед поиском; исходные пользовательские
  названия и ID сохраняются. Обычный элемент без изменения подписи сохраняет
  identity, выбор и состояние ожидающего execute.
- Русская терминология сведена к «рабочая копия» и «снимок».

В ядре сохранены русский формат заголовков vault «Цель/Заметки» и фиктивное
содержимое demo. Это формат пользовательских документов и тестовые данные,
а не локализуемые UI-подписи. Смена заголовков vault потребовала бы миграции
и затронула бы защиту пользовательской секции. Не переводятся имена файлов,
названия планов/вкладок, комментарии пользователя, Git output и протокольные
обёртки текста, отправляемого агенту. Англоязычные диагностические исключения
разработчика также не являются UI-шаблонами.

## Проверки и границы

- Core/RPC: review delivery, review wire, palette wire, setup wizard, Codex
  hook runtime, Git rewrite, contracts. Все проверки сохраняют assertions
  безопасности, доставки, confirm token и запрета неподтверждённых hooks.
- Unit: каталоги, plural boundaries, смена en/ru/fallback, числа/даты, коды,
  workspace/checkpoints/diff, quota/time. Есть проверка реального `_copy_app`
  из сборщика deb: отдельный процесс с `-I` загружает перевод из скопированных
  файлов без source checkout. Сравниваются исходные PO и точные MO bytes,
  проверяется совпадение placeholders в обоих языках и во всех plural формах.
- GUI: новый refused-comment тест проверяет перевод итогового toast и
  сохранение черновика; тест палитры проверяет локальную подпись и буквальный
  пользовательский текст с фигурными скобками. Старые проверки identity,
  shortcuts, approval, review, health, setup и большие планы сохранены.
- Import-linter: 6 kept, 0 broken. ID enum отделён от msgspec observation
  structs, чтобы domain не получал транзитивную зависимость от msgspec.

Полный общий core-набор и установка deb в систему не выполнялись. Нет
утверждения, что весь GUI-набор прошёл: исходный и текущий общий прогоны
сохраняются отдельно, вместе с прицельной проверкой изменённых областей.

## Surprises & Discoveries

- Первый общий GUI-прогон: 415 passed/9 failed. Он выявил моё ненужное
  пересоздание элементов палитры и старые ожидания десятичной точки/сокращения
  дня; identity исправлена в реализации, тесты выбора не ослаблялись,
  форматы теперь проверяются отдельно на en/ru.
- Переход health на локальное пояснение потребовал обновить ожидание:
  warning сохраняет внешнюю диагностику и добавляет руководство README;
  info показывает сам результат и не утверждает наличие риска.
- Общий прогон после исправлений палитры: 427 passed/5 failed,191.30с.
  Два health expectation исправлены после этого прогона и проверяются в
  окончательном прицельном наборе. Оставшиеся clipboard/scale проверены
  сравнением с исходным коммитом; пороги скорости и assertions clipboard
  не менялись.
- Первые контрольные копии не содержали migrations, затем tools. Их отказы
  старта/collection не считаются дефектами продукта или результатом приёмки.
  Итоговый baseline runner извлекает полный git archive 249eb00f.
- Один перекрывавшийся GUI-прогон прерван SIGTERM: gtk-interrupted-results.xml.
  Результат не считается завершённым. Окончательные GUI-прогоны и снимки
  выполняются последовательно в отдельных Xvfb.
- Использованы нативный UI venv и PYTHONPATH этого worktree, временные
  Xauthority/config/state/cache; Xvfb извлечён из deb без установки.
  Рабочее окно, демоны, контейнеры и БД пользователя не менялись.

без заявления буквального соответствия отсутствующему документу.
