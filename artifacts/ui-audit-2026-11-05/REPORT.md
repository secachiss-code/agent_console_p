## 2. Подтверждённые функциональные дефекты

### F1. Поиск не пересчитывается после переименования вкладки — P1

**Воспроизведение:** включить поиск по `UNIQUE-SEARCH-AUDIT`, затем получить `TabUpdated`, меняющий название существующей вкладки на этот текст. Найдено 0 строк вместо 1.

**Причина:** `TabsViewModel._retitle()` меняет свойства существующих объектов, но `TabSidebar` инвалидирует фильтр при изменении модели или запроса. Подписки на свойства, используемые поиском, отсутствуют. Изменение section-key обновляет только сортировку.

**Код:** `src/aconsole/ui/viewmodels/tabs_vm.py`, `_retitle`; `src/aconsole/ui/views/tabs/sidebar.py`, `_model_changed`, `_matches`, `_section_changed`.

**Исправление:** пересчитывать фильтр при изменении title/subtitle/detail/section-title и обновлять empty state; сохранять текущий выбор по id, если вкладка остаётся видимой.

**Приёмка:** вкладка появляется и исчезает из результатов при переименовании и изменении остальных поисковых полей без повторного ввода запроса.

### F2. Внешнее обновление настроек стирает несохранённые правки — P1

**Воспроизведение:** показать настройки rev=1, ввести `User unsaved font`, принять rev=2 с изменённой темой. Поле шрифта становится пустым.

**Причина:** `PreferencesDialog._show_settings()` заново заполняет все поля при получении новой версии. Черновик формы не отделён от подтверждённых настроек.

**Код:** `src/aconsole/ui/views/setup/preferences.py`, `_show_settings`; подписка на `PreferencesViewModel`.

**Исправление:** хранить исходную версию и черновик отдельно; обновлять только нетронутые поля, при конфликте давать выбор. Закрытие изменённой формы должно явно учитывать несохранённые правки.

**Приёмка:** обновление темы или другого независимого параметра не стирает введённый шрифт; конфликт версий не приводит к незаметной потере данных.

### F3. Запоздавший diff показывает уже неактуальный файл — P1

**Воспроизведение:** задержать ответ `_load_file('removed.py')`, загрузить новый пустой summary, затем отпустить ответ файла. `selected_path=None`, но `_show_diff` вызывается для `removed.py`.

Проверка управляла порядком ответов и перехватывала вызов отрисовки; это воспроизведение гонки на уровне компонента, без настоящего Git-репозитория.

**Причина:** `_generation` списка и `_file_generation` файла независимы. Очистка списка не инвалидирует запрос файла.

**Код:** `src/aconsole/ui/views/review/page.py`, `load_changes`, `_show_files`, `_load_file`.

**Исправление:** инвалидировать ожидающий ответ при замене/ошибке списка и проверять актуальность выбранного пути перед отрисовкой. Общая версия контекста должна связывать tab, summary и file.

**Приёмка:** старый ответ не заменяет пустое состояние или сообщение ошибки; быстрые переключения файлов не показывают чужой diff.

## 5. Предлагаемый порядок стабилизации

1. **Корректность данных:** F1–F3; по регрессионному сценарию на каждый дефект. Дополнительно сохранять черновик комментария и локальные правки формы при ошибках.
2. **Восстановление:** видимый запуск/обрыв связи, явный retry, корректное истечение согласований, восстановление после отказа терминала. Ввести единый набор состояний loading/ready/empty/error/stale для экранов.
3. **Контекст работы:** постоянная идентификация проекта и вкладки, проверка переходов «терминал → review → Git → назад», выбор режима рабочей копии, компактный режим панелей.
4. **Критерии выпуска:** автоматизировать переходы с задержанными ответами и ошибками; зафиксировать визуальные эталоны и проверять их, а не только факт появления PNG. Затем длительный прогон с настоящими контейнерами и несколькими агентами.

Предлагаемые критерии выпуска: ни один поздний ответ не меняет другой контекст; сбои имеют видимый способ восстановления; черновики сохраняются; выбранные проект и агент понятны при скрытом sidebar; все основные действия доступны клавиатурой на заявленных размерах и масштабах. Порог задержек и объём нагрузки стоит зафиксировать после замера на целевой машине, а не назначать без измерений.
