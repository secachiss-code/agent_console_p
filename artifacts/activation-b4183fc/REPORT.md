Локальный пакет aconsole_0.1.1_amd64.deb собран из чистого main b4183fc
без загрузки зависимостей. Размер 67589644 байт.
SHA-256: 9529141377225caa069e78909a03312d887205bb63f88ac96ab50cbb3595436b.
Содержимое четырёх изменённых core-файлов в deb и после установки совпало
по SHA-256 с main; значения записаны в verification.json.

Hostrun не содержит install/restart-действия. Узкий хостовый запуск был
согласован через разрешение команды; штатная distrobox-host-exec обёртка
использована после отказа прямого host-spawn. sudo -n потребовал пароль
и ничего не установил. Установка выполнена через системную авторизацию
Polkit: pkexec /usr/bin/dpkg -i локальный пакет, exit 0.

До обновления: ядро PID 21227, одна вкладка, нет pending approvals.
Создана приватная SQLite backup, PRAGMA integrity_check=ok; recovery-токены
сохранены приватно. Файлы БД и токенов в этот отчёт/коммит не включены.
Приватные резервные копии: .aconsole-dev/activation-b4183fc/ (режим 0700).

Штатный CoreClient.replace_daemon выполнил SIGTERM старому core и дождался
освобождения lock, затем запустил установленный core (первый PID 174407).
На финальной сверке наблюдался повторный новый PID 174617;
актуальный PID и exe записаны в verification.json. Данные и версия проверены повторным IPC-клиентом.
SIGKILL не применялся; процессы агента не останавливались. Сохранены одна
вкладка и native session ID; потерянных ранее наблюдаемых процессов агента нет.
Это проверка настоящего установленного процесса, не тестового daemon.

Свежий MCP после активации штатно освободил просроченные verifying, вернув
их в pending для повторной проверки. По существующим подтверждённым
коммитам/отчётам через claim -> attach -> node_update(done) завершены:

- CORE-7 — 7152c72, MCP 18 PASS, full core 1757 PASS, свежий full 1766 PASS.
- PERF-3 — 4a487fc, targeted 27 PASS, full 1747 PASS и последующие 1757/1766 PASS.
- PLAN-3 — b4183fc, targeted 97 PASS, full 1766 PASS, HTTP/IPC/restart PASS.

Живой граф: done вырос с 10 до 13, total 75. Остаток: pending 56, blocked 4,
failed 2, verifying 0, in_progress 0 на момент итогового read-only чтения.
Прямая запись в рабочую БД для изменения статусов не использовалась.
Другие 22 старых verifying не принимались массово: им нужны собственные
проверки и результаты, а обязательные native CLI/GUI нельзя заменить full core.

Финальный независимый UI-role клиент на хосте подтвердил PID, набор вкладок,
native session ID, installed hashes и done=13 через штатный app/snapshot.
Окно UI не закрывалось и отдельно не перезапускалось; актуальность данных
подтверждена на настоящем IPC/MCP. Визуальный скриншот не заявляется.
