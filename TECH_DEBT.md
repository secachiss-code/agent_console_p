# Технический долг AConsole

## TD-HDG-MEM-1 — обоснование и достижение бюджета памяти H-DAG, P2

Открыт 2026-11-16 по прямому решению пользователя: «Согласен. внеси в долг и
закрывай вершину. После коммит и пуш в main». Закрытие рабочей вершины означает
принятие этого долга человеком; исходный красный Tier 3 не превращается в PASS.

Закрыта **DB-0 / node-638 в plan-636** через штатный human IPC с заметкой и
решением `kb-703`. Основная доска: 24/29 done, остальные пять L0 не затронуты.
Отдельный приёмочный plan-7/ACC-0 сохраняет техническое состояние blocked.
[Протокол закрытия](artifacts/hdag-0.1.3/memory-debt-closure.json).

120 МиБ для ядра — целевой критерий плана, а не подтверждённая измерениями
достижимость нынешнего стека. Исходный план местами использует «МБ», runtime
сравнивает именно МиБ. Последний настоящий Tier 3: core RSS **175,81 МиБ**,
UI RSS **123,57 МиБ**, пять восстановленных вкладок и пять вершин. UI в трёх
компонентных циклах достигал **143,38 МиБ**. Это не замер пяти одновременно
работающих CLI и не суммарная физическая память всего приложения.
Временный migration worker отдельно достигал **86,88 МиБ**; его стартовый расход
прибавляется к памяти родителя. Устойчивый рост или OOM этими прогонами не доказаны,
поэтому приоритет P2; подтверждённые OOM/неограниченный рост повышают его до P1.

Сделано: освобождение удерживаемых GTK-виджетов, Cairo до импорта Gtk с сохранением
явных graphics overrides, отложенная загрузка диалогов, освобождение миграционных
зависимостей через завершающийся worker. Глобальная lazy-политика SDK не дала
устойчивой экономии работающего daemon и не включена в продукт.

Условия погашения, последовательно:

1. Зафиксировать состав учитываемых процессов и метрик: RSS каждого процесса,
   PSS/private и память всего набора, включая CLI, проверки, tmpfs и временные
   workers. Разделить простой, прогретую работу и стартовый пик.
2. Повторить холодный/прогретый сценарии с пятью реальными активными вкладками
   и репрезентативным проектом; сохранить несколько повторов и длительную нагрузку.
3. Измерить вклад активных MCP/Pydantic/ORM и кэшей. Проверить прототип официального
   low-level MCP server с прежними схемами, auth/session pinning, ролями и gates;
   принимать изменение по памяти работающего сервера и security regression.
4. Либо подтвердить исходные 120 МиБ, либо отдельно согласовать обоснованный
   бюджет на той же нагрузке и оформить новую ревизию критериев. Постоянный worker
   вне счётчика ядра и подстановка PSS вместо RSS долг не погашают.

Доказательства: [отчёт](artifacts/hdag-0.1.3/memory-followup/REPORT.md),
[последний Tier 3](artifacts/hdag-0.1.3/memory-followup/tier3-current.json),
[компонентный UI](artifacts/hdag-0.1.3/memory-followup/ui-current.json),
[пик worker](artifacts/hdag-0.1.3/memory-followup/migration-peak.json).

**0.1.4, 2026-11-19.** По решению пользователя превышение целевых 120 МиБ
остаётся в TD-HDG-MEM-1. Снижение RSS отложено в рамках этого долга.
На стенде с пятью восстановленными вкладками MEM-1 измерил **173,125 МиБ**.
Это на **53,125 МиБ** выше порога Tier 3 и укладывается в регрессионный
бюджет MEM-1 **183,81 МиБ**. Для шести направлений L0 плана `plan-900`
по-прежнему нужны свежие квитанции direction. [Замер MEM-1](artifacts/0.1.4/rss.md).

**Решение по MEM-0 (`kb-973`).** Пользователь распорядился закрыть вершину
с переносом превышения бюджета памяти в этот долг. Последний живой замер
ядра составил **208,32 МиБ RSS** при четырёх активных вкладках, на **88,32 МиБ**
выше лимита Tier 3. Для контрольного замера Tier 3 требуется минимум пять
активных вкладок. После явного решения пользователя принять вершину без
Tier 3 `MEM-0` переведена в `done` через приёмку с долгом. Решение
`accept_direction_debt` сохранено в журнале вместе со ссылкой на этот долг.
[Отчёт о готовности Tier 3](artifacts/0.1.4/direction-readiness.md).

Runtime-пороги и проверки квитанций этим решением не ослабляются. Полная GUI/CLI
приёмка, прежние UI geometry/focus/visual-baseline отказы и отложенный пользователем
глобальный Ruff baseline остаются отдельными незавершёнными условиями выпуска.

## TD-SEC-7 — доступ агента к данным хоста, P1

По прямому решению пользователя SEC-7 перенесён в долг, исходный узел закрывается.
При доступном на запись домашнем каталоге хоста агент может менять базу AConsole,
файлы запуска оболочки и пользовательские службы. Предупреждения в мастере и health
не устанавливают файловую изоляцию. Пересоздание контейнера в этом закрытии не выполнялось.

Условие погашения: выбрать необходимые монтирования, пересоздать контейнер без
доступа к базе и файлам запуска хоста, затем подтвердить отказ чтения/записи там,
где доступ запрещён, при сохранении доступа к рабочему проекту.
Существующее описание: [ISSUES.md, пункт 6](ISSUES.md#6-домашний-каталог-хоста-в-контейнерах-агентов--p1-частично).
