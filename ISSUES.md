# Журнал проблем AConsole — состояние на 2026-11-09

Обновление рабочей ветки APR-5–8 / QA-6 от 2026-11-14: режимы Claude, Codex и
OpenCode подключены в подтверждённом объёме; автоматические режимы Cursor недоступны.
QA-6 не даёт разрешения на выпуск: файловая граница SEC-7 остаётся открытой, а
Cursor не имеет завершённого tool-level baseline. Изменения не установлены в
работающее приложение. Итог и доказательства — [QA-6](artifacts/qa6/REPORT.md).
Срезы `main` от 2026-11-09 ниже сохранены как история, а не актуальный live-план.


Позднейшее решение пользователя: SEC-11, SEC-13 и SEC-35 приняты и закрываются
с переносом неустранённых проблем в [технический долг](TECH_DEBT.md).
Исторические статусы и результаты ниже сохранены на дату этого журнала;
закрытие этих трёх узлов по решению пользователя не означает security PASS.

Журнал фиксирует, что в **текущем коде** (`main`) работает не так, как заявлено, и что ещё
открыто. Отдельно отмечено, что уже вошло в выпущенный пакет **0.1.1**, а что исправлено
после него и ещё не выпущено.

## Открытые проблемы

### 1. CI на `main`: покрытие ниже порога — P1

**Симптом.** В прогоне на `cc28325a` все шаги, кроме объединения покрытия, проходят: lint и
контракты, core-тесты, UI-тесты, сборка и установка `.deb`. Шаг `coverage report` завершается
с `Coverage failure: total of 88.84 is less than fail-under=90.00`.

**Влияние.** Критерий выпуска 0.1.2 требует полного зелёного прогона. Сейчас зелёный CI
не подтверждён ни для одного коммита после `cc28325a`. Локальные коммиты (10 штук) в CI
не отправлены.

**Следующий шаг.** Поднять покрытие тестами или явно решить с владельцем изменение порога;
затем отправить коммиты и дождаться прогона. Узел QA-4.

### 6. Домашний каталог хоста в контейнерах агентов — P1 (частично)

**Симптом.** По данным SEC-7, в контейнер агента может быть смонтирован на запись домашний
каталог хоста. Тогда агент получает доступ к базе AConsole, `~/.bashrc` и
`~/.config/systemd/user`. Запись в `.bashrc` означает выполнение кода на хосте.

**Что сделано.** Проверка `container_isolation` в мастере и `setup/checks` читает
`podman inspect --format '{{json .Mounts}}'` для каждого `agent-*` и предупреждает о
чувствительных монтированиях. Ошибка inspect считается неизвестной изоляцией. Предупреждение
не меняет контейнеры.

**Почему не закрыто.** Подтверждённая изоляция требует, чтобы пользователь пересоздал
контейнеры: AConsole их не создаёт. Код ядра не может запретить переключение режима, пока
агент может править базу напрямую. Узел SEC-7 — `blocked`.

**Следующий шаг.** Пересоздать контейнеры по шаблону из [README.md](README.md) без прежних
монтирований и повторить диагностику в мастере. Проверку mounts нельзя считать полным аудитом
изоляции.

### 9. Покрытие режимов согласования — P2 (частично)

Глобальные и проектные поля сохраняются; проект заменяет режим и подрежим. Изменение
разрешено только UI. APR-5/6/7 подключают политику, APR-8 реализует предусмотренный
запасной вариант для неподтверждённого Cursor, APR-10 исправляет сохранённый проектный
черновик и защиту выхода. Режим «Сценарий» остаётся недоступным stub.

| CLI | Подтверждённое покрытие |
| --- | --- |
| Claude2.1.318 | PreToolUse/PermissionRequest, auto allow/deny, fail-closed daemon failure; новый deny также статический. |
| Codex0.169.0 | Проверенные local hooks, панель, раздельное согласование escalation; timeout/потеря UI/ошибка hook блокируют. Hosted tools не покрыты. |
| OpenCode2.1.2 | Статический deny и allow+allow; allow+ask частичен: точные pwd/git-inspection без аргументов. Запросы native. |
| Cursor2026.11.13 | Успешный инструментальный baseline не получен. Ask native; auto modes недоступны и не запускают обычный agent вместо запрета. |

«Разрешать» с опасными вызовами в ask закономерно сохраняет вопросы. Для полностью
автоматического режима требуется отдельное подтверждение «Опасные тоже разрешать».
У Codex это также отключает sandbox, что явно показано в UI.

Отчёты: [APR-5](artifacts/apr5/REPORT.md), [APR-6](artifacts/apr6/REPORT.md),
[APR-7](artifacts/apr7/REPORT.md), [APR-8](artifacts/apr8/REPORT.md),
[сохранение настроек](artifacts/apr10/REPORT.md). QA-6 не пройден целиком:
см. [итоговую проверку](artifacts/qa6/REPORT.md), включая незакрытый TD-SEC7.

Следующий шаг: успешный baseline Cursor → hooks/failClosed/static matrix на том же
пути; изоляция файлов и независимая security-приёмка. Сохранять настройки не равно
обновлять установленный код: эта рабочая ветка не устанавливалась в приложение.

### 10. У OpenCode и Cursor нет inline-согласований и авточекпоинтов — P2

**Симптом.** Запросы этих агентов остаются нативными запросами терминала. Чекпоинт перед
промптом не снимается. Статус вкладки определяется по тишине экрана в sidecar.

**Причина.** В `CAPABILITIES` у обоих агентов `hooks`, `approvals`, `checkpoints` равны
`False`. Экранное наблюдение (`ACONSOLE_SCREEN_WATCH=1`) включено для Cursor и OpenCode.

**Что изменилось.** HAR-4 закрыт в плане: экранное ожидание сохраняется при вводе, а UI
подсказывает, где ответить. Проверки на живых CLI этим не заменяются (§30).

**Следующий шаг.** Перед включением inline подтвердить блокировку сервера до ответа
и отображение запроса в TUI. APR-6 оставил OpenCode native; APR-8 не объявляет hooks Cursor проверенными.

### 26. Git-драйверы и вызовы Git вне runner выполняют код репозитория — P1

**Симптом.** По сверке SEC-8 на реальном git (узел SEC-11, `failed`):

- `filter.<имя>.clean` и `filter.<имя>.process` из конфигурации репозитория выполняются на
  хосте при `status` и `diff` через `GitRunner`;
- `gpg.program` выполняется при `commit`;
- часть вызовов Git в `infrastructure/tabs.py` и `mcp/tools.py` идёт в обход runner, а
  проверка покрывает только `infrastructure/git`.

**Причина.** SEC-8 закрыл фоновые пути (`core.fsmonitor`, `core.hooksPath`, `diff.external`,
textconv), но не драйверы фильтров, подписей и вызовы вне runner.

**Влияние.** Агент, который может править конфигурацию репозитория, может выполнить
произвольную программу на хосте при обычной работе AConsole. Это выход за пределы изоляции
контейнера.

**Следующий шаг.** Перекрыть `filter.*` и `gpg.program` во всех вызовах Git. Перевести
оставшиеся вызовы на runner и расширить проверку на весь `src/aconsole`.

## Ограничения, унаследованные от 0.1.0

| Ограничение | Влияние |
|---|---|
| Однопользовательский режим | нет серверного и multi-user развёртывания |
| Пакет только `amd64`, без GPG-подписи | целостность только по SHA-256 |
| Scope файлов не изолирует параллельную запись | нужны отдельные worktree; внешние редакторы не блокируются |
| Выборочной отмены вклада агента нет | нельзя откатить один ход, не откатив чекпоинт целиком |
| Автоматического запуска цепочек по DAG нет | план — доска, а не оркестратор |
| AConsole не создаёт контейнеры и не логинит CLI | мастер только сообщает, что сделать |
| Cursor и OpenCode используют непубличные endpoint'ы лимитов | формат может измениться без предупреждения |
| Вложения PNG подтверждены только в Codex | в Cursor путь остаётся текстом; Claude и OpenCode не проверялись |
